# Passage · 旅行工作台

把散落各处的旅行攻略，收敛成**一条走得通的路线**。

一个零构建的静态原型：地图工作台上把小红书笔记里的地点摊开、按营业时间排出顺序、
串成一条路线，点开每一处能看到实拍配图与实用信息。

> 当前数据：**中山 · 澳门（17 处地点 / 2 天 / 24 张配图）**
> 第 1 天中山（傍晚）18:00 中山站 → 松本寿司 → 圆宝阿公；第 2 天澳门（全天）06:45 拱北口岸过关 → 半岛 → 路环 → 氹仔。

## 跑起来

```bash
python3 -m http.server 8777 --bind 127.0.0.1
# 打开 http://127.0.0.1:8777/
```

（在仓库根目录执行。页面本身就是站点根，`index.html` 直接可访问。）

> ⚠️ 必须走 http 服务，**不能双击 `file://` 打开**——地图瓦片是跨域请求，`file://` 下会被浏览器拦截。

零依赖安装、零构建。地图用 MapLibre GL JS 5 + OpenFreeMap（不需要 token）。
**地图库已随仓库内置**（`vendor/maplibre/`，v5.24.0，BSD-3-Clause）——不再依赖 CDN，
clone 下来断网也能起，也不会因为某个 CDN 抽风就整块地图变白。

## 两个视图

| 视图 | 地址 | 内容 |
|---|---|---|
| 行程总览 | `#home` | 行程规模统计 + 每天路线卡 |
| 地图工作台 | `#map` | 三栏：行程面板 / 鸟瞰地图 / 地点详情卡 |

> 两天以上的行程，行程面板会出现「总览 / 第 1 天 / 第 2 天」三个 tab，按天着色。
> 半天行程（<3 个地点的日期）会有提示「可排序的地点少于 3 处，没有可优化的折返」。

## 核心能力

- **倾斜鸟瞰地图**：pitch 50°、3D 建筑挤出（zoom ≥ 14）
- **按天着色的横向椭圆编号标记**：`1-1`…`1-3`、`2-1`…`2-14`，宽度随编号长度走，
  两位数标签横展不再被圆裁掉；城市尺度下自动做屏幕空间避让
- **彩色虚线路线** + 相位平移的「流动」动画
- **路线自动排序**：最近邻 + 2-opt，带前后距离对比、一键撤销、起点锁定。
  建议性、不自动生效——「总距离最短」不总是对的目标
- **地点详情卡**：1–2 张实拍配图（点图看大图）+ 计划时间 / 地址 / 营业时间 / 电话 / 价位 / 怎么去 / 坐标精度
- **详情卡可关闭**：右上角 ×、Esc、点地图空白处；未选中时按钮自动隐藏
- **手机可用**：竖屏是底部抽屉（面板收起成一条、点标题栏展开），横屏换成左列表 + 右详情；
  触控目标统一 ≥44px，地图标记用透明伪元素把可点区域撑大
- **数据与渲染完全解耦**：`app.js` 里没有城市名、天数、地点数量、产品名的硬编码，
  换城市只改 `data/places.js` 的 `CITY` / `DAYS` / `PLACES`；换产品名只改 `APP.name`

## 几个结论

**开源社区有「功能基座」，没有「产品形态」。**
[`liketrek/TREK`](https://github.com/liketrek/TREK)（AGPL-3.0）对行程 / 协作 / 预算 / 附件 / 导出 / 离线等 8 项能力全覆盖，
一条 `docker run` 就能起。但没有任何开源项目做「视觉叙事型个人旅行工作台」——
TREK 是**工具型**（把旅行管起来），参照的笔记是**叙事型**（把旅行记住并讲出来），信息架构从根上不同，**换皮做不出来**。
所以正解是 TREK 当后端 + 自建体验层。详见 [`docs/01`](docs/01-开源方案调研报告.md)。

**「总距离最短」是错的优化目标。**
参照笔记的 Day 1 手工顺序末段刻意绕远，是为了过江看夜景。纯距离最优会把它反过来。
本行程里也有同一个道理：路环的 7 处不是按「怎么走最近」排的，而是按「什么时候到最好」——
黑沙海灘被排在 18:25 到，是为了看日落（代价是天色已暗，见 `docs/04` 的 ⚠️ 提示）。
所以自动排序做成**建议性**的：给你一个更短的备选，并告诉你省了多少，留不留你决定。详见 [`docs/03`](docs/03-技术实现方案.md) §4.2。

**顺序被营业时间卡死。**
**第 1 天中山** 中山站按用户指定 18:00 出发；松本寿司 10:30 开门但 20:00 打烊，必须赶上晚餐时段的尾巴；
圆宝阿公 13:00 才开始叫号入座，定位是夜宵/糖水冰。
**第 2 天澳门** 起点是**拱北口岸**（珠海侧）——它每日 06:00 开关、次日 01:00 关闸，不是 24 小时通关，
所以 06:45 到口岸已是当天最早的合理时间，过关后步行到祐汉正好接上 07:00 开门的好利是。
再往后：薈真集 10:30 才开门所以早餐后要留两小时空档，鐵餅號 12:00 才开门且**周一店休**，
糖朝盛世 15:00 才开门只能做收尾。
路环并入下午也不是随便并的：半岛段 14:00 在 Bamu 收尾后才能动身过江，
到路环正好 14:45，糖水接在最后。逐条约束与后果见 [`docs/04`](docs/04-行程清单-中山与澳门.md)。

## 数据来源与可信度

| 字段 | 来源 |
|---|---|
| 地点清单 / 正文 / 推荐菜 | 用户提供的 9 条小红书笔记链接 |
| 中山站 / 拱北口岸 | **用户指定的起点**（非笔记来源），坐标取自 OSM 节点，通关时间来自第三方口岸指南 |
| 松本寿司 地址 / 电话 / 营业时间 / 人均 | 城市吧 city8 商户页（转引第三方数据，未与店家官方渠道核对） |
| 圆宝阿公 背景 / 价位 | 中山网 2026-07-23 探店报道；派号 / 叫号规则、必点品项来自笔记正文 |
| 配图 | 各笔记的实拍照片，原图，未二次创作 |
| 地址 / 营业时间 / 电话 / 价格 | 笔记里的门店照片与菜单照片，或店家官网 / 商户名录（逐条标注来源） |
| 拱北口岸通关时间 | 珠海本地宝与澳门114的口岸指南（第三方，**未与口岸官方渠道核对**） |
| 坐标 | `photon.komoot.io`（OSM 数据），按楼名 / 街道名检索，逐条标注精度 |
| 门牌反查 | `webmap.gis.gov.mo` 街道门牌查询系统 |

**营业信息未与店家或口岸官方渠道全部二次核对**，出行前建议电话确认。

## 验证

原型的关键改动都用无头 Chrome + CDP 跑过端到端断言（配图加载、三种关闭方式、大图开关、
排序收益数字、两天结构与退化保护、无 JS 异常）。移动端另有布局量化脚本，覆盖 5 种机型 × 3 种状态，
测底部溢出、横向溢出、页面滚动高度与触控目标尺寸。
方法与被踩过的坑记录在 [`docs/05-原型实现说明.md`](docs/05-原型实现说明.md)。

自动化脚本统一收集在 `/tmp/tw_*.js`，需要新加断言时复制最近的一个脚本为模板、
改成按 `data-id` 定位地点（不要按行号索引——加一天就全错位）。
