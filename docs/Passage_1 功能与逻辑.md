## 二、核心交互流程

### 流程 A：从零到一份行程（行前）

```
打开首页（行程总览）
   ↓ 点「新建行程」
选城市（v1：澳门）+ 天数
   ↓
系统给出「推荐路线」候选（基于预置攻略库）
   ↓ 用户勾选想去的 / 划掉不想去的
   ↓
地图工作台生成：每天自动分组 + 按地理集中度排序
   ↓ 用户拖拽微调（地点可在天之间拖）
   ↓
点任意地点 → 详情卡展开 → 看吃什么、看什么、停留多久
   ↓
行程定稿 → 生成只读分享链接 / 导出
```

### 流程 B：旅行当天使用（行中）

```
打开首页 → 行程总览 → 点「第 2 天」卡片
   ↓
带着当天筛选状态进入地图工作台
   ↓
看到当天路线（彩色虚线 + 编号标记）
   ↓ 点「下一个地点」
   ↓
镜头飞近 + 详情卡展开（含导航跳转按钮）
   ↓
一键跳转外部地图导航
```

> **v1.1 移除**：原流程 C「回来后整理成纪念品」已删除。产品在 S2 结束后即完成交付，不承担行后环节。

## 三、迭代路线（原 Passage_2e §一）

| 阶段 | 目标 | 交付物 | 成功标志 |
|---|---|---|---|
| **Phase 0** 验证 | 确认需求真实 | 可点击原型（Figma 或 HTML） | 5 位目标用户中 ≥3 位表示「会用」 |
| **Phase 1** MVP | 跑通「行前规划」主流程 | 单城市（澳门）+ 地点 + 行程 + 地图工作台 + 详情卡 | 用户能独立完成一次行程规划 |
| **Phase 2** 提效 | 让规划更快更省事 | 路线自动排序 ✅ + 攻略导入 + 离线 + 导出 | 规划耗时下降 50% |
| **Phase 3** 扩展 | 从单城市到可运营 | 多城市 + 内容管理后台 | 新城市上线周期 < 1 周 |

**v1.1 路线图调整**：原 Phase 2「补全双主场（旅行箱 + 手帐）」整段删除，原 Phase 3 提效上移为 Phase 2，原 Phase 4 平台化上移为 Phase 3。产品不再需要「行后留存」这一环，路线图从 5 阶段收缩为 4 阶段。

**关键判断点**：Phase 1 结束后回访用户，验证的不再是「有没有人用行后手帐」，而是**「自动排序给出的路线，用户会不会照单全收」**。如果用户每次都要手工调整，说明排序算法的目标函数与真实偏好不一致——这是现在最大的产品风险。前端主体已成型后，瓶颈已从「技术可行性」转移到**内容生产**与**数据来源可信度**；下一步边际收益最高处不在加功能，而在把已入库地点的信息核实一遍（缺口清单见 `Passage_3b` §三）。

> 各阶段实际进度与逐项完成情况不在本文维护，一律以 `Passage_3 交付状态.md` 为准。

## 四、验收标准（原 Passage_2e §二）

### 功能验收

- [ ] 能从零创建一份行程，且每天地点地理集中
- [ ] 地图为倾斜鸟瞰视角，缩放时建筑有立体感
- [ ] 点击地点，镜头平滑飞近且不卡顿
- [ ] 每天路线颜色不同，虚线跟随地图移动
- [ ] 地点详情卡字段齐全，资料来源可点击
- [ ] 自动排序给出前后距离对比，且可一键撤销、可锁定起点
- [ ] 行程总览页正确显示规模统计与每日路线卡，点击某天能带着筛选状态进入地图
- [ ] 自动排序后不出现明显折返，且能显示总距离的改善幅度
- [ ] 自动排序可撤销，能回到手工顺序
- [ ] 768px 以下布局正常，行程面板可收起

### 体验验收

- [ ] 首次进入 5 秒内能明白「这是什么产品」
- [ ] 完成一次行程规划不超过 10 分钟
- [ ] 开启「减少动效」后无任何眩晕性动画
- [ ] 移动端 4G 弱网下首屏可加载（骨架屏 + 渐进增强）
- [ ] 离线状态下能打开已缓存的行程

### 质量验收

- [ ] Lighthouse 性能 ≥ 85（移动端）
- [ ] 所有地点信息有来源与核实日期
- [ ] 无版权风险的素材（插画原创 / 照片授权）
- [ ] 键盘可完成核心操作

## 五、开发顺序建议（原 Passage_2e §三）

按「先验证风险，后堆功能」排列。逐项进度以 `Passage_3 交付状态.md` 为准，这里只留计划序与判断依据：

1. **地图可行性验证**：MapLibre + OpenFreeMap 起页面，确认 3D 建筑、pitch 50°、路线虚线、flyTo 全部可用——关键路径，唯一「可能推翻视觉方案」的技术风险。
2. **TREK 部署与 API 摸底**：起服务，开启 addon，确认 REST API 能覆盖行程/地点/附件/导出（是否接 TREK 见 `Passage_3b` §一 决策 #1/#3，用户已拍板暂缓）。
3. **数据模型落地**：建内容库表结构，灌入示范数据（原型阶段用 `data/places.js` 顶替）。
4. **地图工作台**：行程面板 + 地图 + 详情卡三栏联动（含移动端抽屉降级）。
5. **路线自动排序**：最近邻 + 2-opt + 起点锁定 + 预览/撤销。
6. **移动端与离线**：响应式 + PWA + 离线降级。
7. **内容补全与打磨**：逐条入库、核实来源（口径见 `Passage_2f`）。
