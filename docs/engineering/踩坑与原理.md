# engineering · 踩坑与原理

> **职责**：规则的成因、判据与排障实录——为什么必须这么做。
> **体积**：5.3 KB ｜ **更新**：2026-09-28（文档体系重构时自旧 0X 文档拆出）
> **上级索引**：`Passage_0 文档地图.md` §3
> **本文不包含**：现行纪律条文 → `AGENTS.md` §5–§8（这里是「为什么」，不是「是什么」）
> ⚠️ **什么时候读本文**：**排障 / 质疑某条规则时**读。

---

1. **MapLibre 的 `load` 事件依赖首帧渲染完成**。在后台标签页里 `requestAnimationFrame` 被 Chrome 节流，`load` 永不触发，地图一片空白。改用 `style.load`（样式解析完就触发，不依赖渲染）。
2. **矢量瓦片只在渲染帧里才会被请求**。所以「后台标签页里地图空白」是假象——不是代码问题。调试地图时务必在前台窗口看。
3. **无头浏览器里 WebGL 需要额外开关**。只加 `--disable-gpu` 会让 WebGL 初始化失败（`Could not create a WebGL context`），必须用 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`。这一点也促成了一处**真实加固**：`new maplibregl.Map()` 现在包在 try/catch 里，失败时显示降级提示而不是整块空白。
4. **CSS `display:flex` 会覆盖 `[hidden]` 属性**。已统一加 `[hidden]{display:none !important}`。
5. **虚线动画不要用 Mapbox 官方示例的 `[0,4,3]` 序列**——它会让虚线在某些相位几乎消失。改用「dash/gap 恒定 + 相位平移」的 4 元素数组写法。
6. **`CITY.zoom` 不等于运行期 `map.getZoom()`**。`style.load` 后会用 `fitBounds` 把视野收紧到刚好装下所有标记，所以实测 zoom 通常是 14 而不是配置里的 13.6。这是设计如此。
7. **`position:sticky` 是「悬浮在可滚动栏里」的正解**，比 `position:absolute` 好——后者会跟着内容一起滚走。关闭按钮外层用 `height:0` 包裹，这样 sticky 生效又不占位。
8. **列表里别直接用大图当缩略图**。42px 的坑位配 900px 的原图，15 行就是 3.1 MB。改成同目录 `thumb.jpg`（180px）后降到 ~110 KB。缩略图总量这么小，就不必惰性加载了——`loading="lazy"` 反而会在合成滚动场景里出现「滚动后仍有几行不加载」的观感问题。
9. **`overflow-x:auto` 会把元素变成滚动容器，而 flex 的「自动最小尺寸」对滚动容器是 0**。所以 `.daytabs` 加上横滑之后，一旦面板内容超高，它就被压成一条 12px 的线——不是布局算错，是规范如此。要么显式 `flex:0 0 auto`，要么别让它当 flex item。
10. **`100vh` 在移动端不等于可视高度**。地址栏会收放，`100vh` 取的是「地址栏收起时」的高度。用 `100dvh`（带 `100vh` 兜底）才能跟着变。前提是页面别用 body 滚动——`html/body{height:100%}` + 一个 `overflow:auto` 的主区，比「body 自然滚动 + sticky 顶栏」在移动端稳。
11. **标准 `line-clamp` 会改写 `display`**。写了 `line-clamp:2` 之后，`display:-webkit-box` 会被换成 `flow-root`，反倒让 `-webkit-line-clamp` 那套失效。两个别混着写；只写 `-webkit-line-clamp` 就够（Chrome / Safari / Firefox 都支持）。
12. **无头 Chrome 会复用同一个 profile 的 HTTP 缓存**。改完 CSS/JS 再跑测试，可能拿到的还是上一版——现象是「改动没生效」，非常容易误判成代码问题。测试脚本里必须 `Network.setCacheDisabled`。同理，`Page.navigate` 到**只差 hash 的同一个 URL 不会重载页面**，多设备连测时状态会从上一台串过来，要先跳 `about:blank` 或用带随机查询串的 URL。
13. **`python -m http.server` 下 `naturalWidth` 偶发为 0，是测试假阳性，不是图坏了**。它回的是 `HTTP/1.0`（每次响应后关连接），13 张缩略图 + 20 张详情图 + 地图瓦片一起并发时，个别图片会慢到断言跑完还没解码——于是出现 `complete=true` 但 `naturalWidth=0` 这种「看起来像坏图」的组合。**判据是三条一起看**：`file` 能认出 JPEG、`curl` 取回的字节 md5 与磁盘一致、`sips` 能读出像素尺寸。三条都过就是时序问题，修法是断言前轮询就绪或多等一拍，别去改代码。
14. **并行跑多个无头 Chrome 实例会互相拖慢，固定 `sleep` 等页面就绪不可靠**。同一台机器上并行跑桌面回归 + 移动端截图 + 排序测量时，CPU 被 swiftshader 软件渲染吃满，原本 9 秒能渲染完的页面可能十几秒还没跑 JS——现象是「选择器全都取不到值」，很容易误判成应用挂了。改成**轮询就绪条件**（例如等 `.place-row` 数量到位）再断言。另外 `Page.captureScreenshot` 在负载高时可能几十秒不回，CDP 调用要给足超时。
15. **核心渲染库别挂在单一 CDN 上**。`cdn.jsdelivr.net` 抽风时（本机实测 `curl` 返回 000，而瓦片源 `tiles.openfreemap.org` 返回 200），`index.html` 的 `<script src>` 拿不到 MapLibre，地图区直接变成「地图库未能加载」——**看起来像地图代码坏了，其实只是那个 CDN 不通**。排查方式是分别测「库的 CDN」和「瓦片源」两条链路。零构建站点把这类库落到 `vendor/` 更稳，也才对得起「clone 下来就是完整应用」这句话。
