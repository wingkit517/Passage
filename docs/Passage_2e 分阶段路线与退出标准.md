## 二、验收标准

### 功能验收

- [ ] 能从零创建一份行程，且每天地点地理集中
- [ ] 地图为倾斜鸟瞰视角，缩放时建筑有立体感
- [ ] 点击地点，镜头平滑飞近且不卡顿
- [ ] 每天路线颜色不同，虚线跟随地图移动
- [ ] 地点详情卡字段齐全，资料来源可点击
- [ ] 自动排序给出前后距离对比，且可一键撤销、可锁定起点
- [ ] 行程总览页正确显示规模统计与每日路线卡，点击某天能带着筛选状态进入地图
- [ ] 自动排序后不出现明显折返，且能显示总距离的改善幅度
- [ ] 自动排序可撤销，能回到手工顺序
- [ ] 768px 以下布局正常，行程面板可收起

### 体验验收

- [ ] 首次进入 5 秒内能明白「这是什么产品」
- [ ] 完成一次行程规划不超过 10 分钟
- [ ] 开启「减少动效」后无任何眩晕性动画
- [ ] 移动端 4G 弱网下首屏可加载（骨架屏 + 渐进增强）
- [ ] 离线状态下能打开已缓存的行程

### 质量验收

- [ ] Lighthouse 性能 ≥ 85（移动端）
- [ ] 所有地点信息有来源与核实日期
- [ ] 无版权风险的素材（插画原创 / 照片授权）
- [ ] 键盘可完成核心操作

## 三、开发顺序建议

按「先验证风险，后堆功能」排列。**括号内是 2026-09-27 的实际进度。**

1. ✅ **地图可行性验证**：MapLibre + OpenFreeMap 起页面，确认 3D 建筑、pitch 50°、路线虚线、flyTo 全部可用。**已通过**——这一步是关键路径，它是唯一「可能推翻视觉方案」的技术风险，已排除。
2. ⬜ **TREK 部署与 API 摸底**：起服务，开启 addon，确认 REST API 能覆盖行程/地点/附件/导出。**已克隆到 `/Users/wingkit/Developer/trek`，暂缓**（用户决定先完善前端）。
3. 🟡 **数据模型落地**：建内容库表结构，灌入示范数据。**原型用 `data/places.js` 顶替**，已灌入澳门 3 个地点；表结构待后端阶段再建。
4. ✅ **地图工作台**：行程面板 + 地图 + 详情卡三栏联动。**已完成**（含移动端抽屉降级）。
5. ✅ **路线自动排序**：最近邻 + 2-opt + 起点锁定 + 预览/撤销。**已完成并实测**（§4.2）。
6. ⬜ **移动端与离线**：响应式已做；PWA + 离线降级待做。
7. 🟡 **内容补全与打磨**：**进行中**——澳门 3 个地点已入库，营业时间/电话/价格均取自笔记照片，**未与店家官方渠道二次核对**。

**当前阶段判断**：前端主体已成型，瓶颈已从「技术可行性」转移到**内容生产**与**数据来源可信度**。
下一步的边际收益最高处不在加功能，而在把已入库地点的信息核实一遍。
