# 05 · 原型实现说明

> 零构建静态原型的实现说明：怎么跑、实现了什么、数据来源与已知问题、踩过的坑。
> 站点文件已移至仓库根目录。配套：[`02-产品设计方案.md`](./02-产品设计方案.md)（为什么这么设计）· [`03-技术实现方案.md`](./03-技术实现方案.md)（怎么实现）

参照小红书笔记《旅游攻略提前晒🔥ai工作台夯爆了！》实现的**可运行原型**，对应 [`02-产品设计方案.md`](./02-产品设计方案.md) 里的 Phase 1 + Phase 2（路线自动排序）。

零构建、零依赖安装——纯静态站点，原生 JS。

**当前数据：中国澳门 · 半岛与路环（14 个地点 / 1 天 / 20 张配图）。**
拱北口岸过关（06:45–07:25）→ 上午澳门半岛（07:30–14:00）→ 下午路环岛（14:45–19:05）→ 傍晚回氹仔吃糖水收尾（20:25 结束）。

## 运行

```bash
# 在仓库根目录执行
python3 -m http.server 8777 --bind 127.0.0.1
# 打开 http://127.0.0.1:8777/
```

> ⚠️ **不要用 `file://` 直接打开**。地图瓦片是跨域请求，`file://` 协议下浏览器会拦截，底图加载不出来。必须走 http 服务。

## 已实现（对照设计文档）

### 地图工作台

- **倾斜鸟瞰视角**：pitch 50°、bearing -12°，城市尺度下能看到立体感
- **3D 建筑**：直接用 OpenFreeMap liberty 样式自带的 `building-3d` 挤出图层（依赖瓦片里的 `render_height` 字段，zoom ≥ 14 生效）
- **编号标记**：`1-1`…`1-14`，按天着色；两位数编号自动收字号（`.is-long`）
- **标记避让**：城市尺度下地点会挤在一起，用一次屏幕空间松弛迭代把重叠标记推开，位移限制 ±24px
- **路线虚线**：每天一条 GeoJSON 折线（当前数据只有一天，所以只画一条），白色描边 + 彩色虚线，带相位平移的「流动」动画
- **镜头飞近**：点击地点 → `flyTo` zoom 16.2 / pitch 55°，1200ms 缓动
- **三栏联动**：日期 Tab、类型筛选、地点列表、地图、详情卡全部同步
  （天数 ≥2 时才渲染日期 Tab；只有一天时「总览」与「第 1 天」内容完全相同，整行隐藏）
- **降级处理**：WebGL 创建失败或底图加载失败时显示提示条，左侧列表与右侧详情仍可用

### 路线自动排序（v1.1 新增）

面板顶部三个控件：**自动排序 / 撤销 / 起点锁定**。

- **最近邻 + 2-opt**：haversine 距离 → 最近邻生成初始解 → 2-opt 消除交叉路径
- **建议性，不自动生效**：排序后显示收益，用户看得到再决定留不留。**实测（当前澳门数据集，14 处全在一天）**：

  | | 排序前 | 锁定起点 | 放开起点 |
  |---|---|---|---|
  | 全天（14 处，拱北口岸 → 半岛 → 路环 → 氹仔） | 20.9 km | 15.4 km（省 5.5 km，−26.5%） | **15.4 km（省 5.5 km，−26.5%）** |

  两点值得记下来：

  1. **锁不锁起点，结果完全相同（都是 15.4 km）**。拱北口岸在地理上就是全天最北端的地点，
     纯距离最优也会从它出发——所以「起点锁定」在当前数据上不损失任何收益。
     它防的是另一种情况：**首站被硬性指定、但它不在地理端点**（例如必须从酒店出发，而酒店在路线中段）。
  2. **−26.5% 看起来很大，但别误读**。这个数省下来的主要是**半岛内部的折返**，不是「少跑一趟路环」——
     拱北 → 半岛 → 路环 → 氹仔 的单向走法在两种顺序里都躲不掉。手工顺序是照营业时间排的
     （薈真集 10:30 才开、鐵餅號 12:00 才开），代价就是半岛内部来回。所以这 5.5 km 是
     「时间约束换来的距离」，不是排错了。

  > 距离口径：地点之间的 **haversine 直线距离**之和，不是步行 / 公交实际里程，也不是耗时。只用来比较两种顺序的相对长短。
- **一键撤销**：快照存在 `sortSnapshot`，还原到排序前
- **起点锁定（默认开）**：每天第一站（口岸 / 酒店 / 早餐店）不被移动
- **无收益时不动作**：若已是最短，提示「当前顺序已经是最短的，没有可优化的折返」，且不显示撤销按钮
- **免责提示**：文案里明确写「只优化距离，不考虑「把某处留到夜里」这类编排意图」

> **为什么排序不自动生效**：参照笔记的 Day 1 手工顺序是 `新天地 → 豫园 → 外滩 → 北外滩 → 陆家嘴`，
> 末段刻意绕到北外滩是为了**过江看夜景**。纯距离最优会把它反过来——**「总距离最短」是错的优化目标**。
>
> 当前澳门数据里也有同一个道理：黑沙海灘被排在 18:25 到，是为了看日落（代价是天色已暗）。
> 纯距离最优会把它往前提。详见 [`03-技术实现方案.md`](./03-技术实现方案.md) §4.2。

### 地点详情卡

- 头部色块取当天主题色，含类型 / 气质 / 编号
- **配图**（v1.2 新增）：每处 1–2 张来自对应小红书笔记的实拍图，图下带说明；**点图看大图**
- 计划时间（`clock`）作为第一枚胶囊标签，与营业时间并列
- **信息块**（v1.1 新增）：计划时间 / 地址 / 营业时间 / 出炉时间 / 电话 / 价位 / 怎么去 / 坐标精度——**只渲染有值的行**，营业时间后面挂来源标注
- 「先去吃什么」「去哪里看风景」
- 「查看资料来源 ↗」+ 数据来源与核实日期说明

### 关闭详情卡（v1.2 新增）

三条路都能关，不只是装饰：

| 方式 | 行为 |
|---|---|
| 右上角 **×** | 桌面端回到空态提示（右侧栏常驻，不留白）；移动端整块收起浮层 |
| **Esc** | 同上；若大图正开着，**先关大图**，再按一次才关卡片 |
| **点地图空白处** | 同上。标记是独立 DOM 元素盖在画布上，点标记不会误触发 |

关闭按钮用 `position:sticky` 贴在详情栏顶端——卡片滚到哪儿它都在，且外层高度为 0，不占位。
未选中任何地点时按钮自动隐藏（`.detail.is-empty`）。

### 列表缩略图（v1.2 新增）

左侧地点列表每行带一张 42px 缩略图，用同目录下的 `thumb.jpg`（180px，13 张共约 96 KB）。
**拱北口岸没有配图，那一行就不显示缩略图**——`normalize()` 里 `p.thumb` 是从 `imgs[0]` 推出来的，没有 `imgs` 自然是空串。
列表里只占 42px，不该去下 900px 的原图——所以缩略图**预加载**（总量太小，惰性加载反而添乱），
详情卡里的大图才用 `loading="lazy"`。

### 单日行程适配（v1.3 新增）

原数据是「第 1 天半岛 / 第 2 天路环」两天，v1.3 按用户要求把**路环并入第 1 天下午**，全程一天走完。

**数据侧只改了数据，没有一处结构性改动**——这正是「数据与渲染解耦」的兑现：

- `DAYS` 从 2 条减到 1 条，`TRIP.dayCount` 改 1
- 所有地点的 `day` 全部置 `0`，`order` 重排成连续序号（合并时 13 处 → `0–12`；v1.4 加入拱北口岸后为 14 处 → `0–13`）
- 编号不用手改：`renumber()` 按 `(day.index + 1) + '-' + (i + 1)` 自动算出 `1-1`…`1-13`（v1.4 后为 `1-1`…`1-14`）
- 路线图层是 `DAYS.forEach` 建的，天数减到 1，自然只剩 `route-0-casing` / `route-0-line`
- 路环 7 处地点在 `name` 前统一加 **【路环】** 前缀（半岛与路环都在同一天了，得靠名字区分）

**但文案会露馅**。只有一天时，「逐天看」「点一天」「全部 1 天」这些说法读着别扭，所以全部跟着天数走：

| 位置 | 两天时 | 一天时 |
|---|---|---|
| 顶部副标题 | `MACAU · 2 日行程` | `MACAU · 1 日行程` |
| 总览小标题 | 「这 2 天怎么走」 | 「这一天怎么走」 |
| 面板副标题 | 「点一天，看当天的路线」 | 「按时间顺序串成一条线」 |
| 天数标签行 | 总览 / 第 1 天 / 第 2 天 | **整行不显示** |
| 排序作用域提示 | 「全部 2 天」 | 「第 1 天」（而不是「全部 1 天」） |

天数标签行整行隐藏的理由很直接：「总览」与「第 1 天」在只有一天时内容完全一样，留着只是让人多点一次。

**合并的代价要如实写出来**：黑沙海灘现在 18:25 到，而 9 月下旬澳门日落约 18:20——**看到的是暮色里的海滩，
不是原笔记那种大白天**。这一条同时写进了 `data/places.js` 的 `hac-sa.desc` 与 [`04-澳门行程清单.md`](./04-澳门行程清单.md) 的 ⚠️ 提示，
没有藏起来。

### 起点改为拱北口岸（v1.4 新增）

用户指定「我们从拱北口岸出发，所以第一站是拱北口岸」，于是新增了第 14 处地点。
**这处地点和其余 13 处性质完全不同**，因此牵出了三处小改动：

| 差异 | 处理 |
|---|---|
| 它不在澳门，是珠海侧的口岸 | 数据里显式标 `cat: "交通"`，与「餐饮 / 景点 / 街区 / 海滩」并列成为第 5 个筛选大类。**不用改 `app.js`**——`ALL_TYPES` 本来就会把 `CAT_ORDER` 之外的分类追加到末尾 |
| 它不是小红书笔记来源，是用户指定的 | 详情卡底部的「内容来源」原本写死成「用户提供的小红书笔记（正文与配图）」，加一个可选的 **`srcNote`** 字段：数据里给了就用数据的，没给仍走默认。拱北口岸那条写明「用户指定（本次行程起点，非小红书笔记来源）」 |
| 没有配图 | 不需要改代码：`normalize()` 里 `p.thumb` 是从 `imgs[0]` 推出来的，没有 `imgs` 就是空串，列表行直接不渲染缩略图；详情卡的配图容器同理不渲染 |

编号照旧由 `renumber()` 算出 `1-1`…`1-14`，其余 13 处自动后移一位。

> 这是「数据与渲染解耦」第三次兑现：加一处**性质完全不同**的地点（跨城市、非笔记来源、无配图、新分类），
> **`app.js` 只动了 2 行**（`srcNote` 的读取与默认值列表），其余全靠数据。

### 移动端适配（v1.3 新增）

手机上用的是**底部抽屉**：行程面板默认收起成一条（只露标题栏），点标题栏展开；地点详情是更靠前的一层浮层。
横屏（矮屏 + 够宽）换成**左列表 + 右详情**——390px 高的视口里，底部抽屉会把地图压成一条缝。

这一轮修掉的问题，全部是先用脚本量出来的，不是靠肉眼估：

| 问题 | 原因 | 处理 |
|---|---|---|
| 地图底部溢出视口 24px | `#view-map{height:calc(100vh - 57px)}` 里的 57px 是桌面端顶栏高度；窄屏顶栏换行后是 81px | 拆掉写死的数字，改成 `body` 纵向 flex + `#main{flex:1}`，地图高度由剩余空间算出来；同时用 `100dvh` 让地址栏收放时也跟着变 |
| 收起态面板把页面顶出滚动条（文档高 1040 vs 视口 667） | 收起用 `transform:translateY(calc(100% - 152px))` 往下平移，整块被推出视口 | 改成收缩 `max-height`（面板自身 `overflow-y:auto`），不再平移 |
| 收起后露出的高度对不上 | 152px 是写死的，标题换行就错位 | `app.js` 实测标题栏高度写进 `--panel-peek`，CSS 用它 |
| 展开后地点列表只剩几十像素 | 面板内固定块（标题栏+天数+排序+摘要+筛选+底栏）加起来超过面板高度，列表被压成 0 | 面板整体滚动而不是只让列表滚；摘要里的地点串裁成一行；天数与筛选改单行横滑 |
| 天数标签被挤成一条线 | `.daytabs` 加了 `overflow-x:auto` 后成了滚动容器，而 flex 的「自动最小尺寸」对滚动容器是 **0** | 显式 `flex:0 0 auto` |
| 触控目标普遍偏小 | `.nav-btn` 30px、`.daytab` 31px、`.chip` 24px、`.btn-sm` 29px、MapLibre 控件 29px | 窄屏统一抬到 ≥44px（Apple HIG / Material 下限） |
| 地图标记点不中 | 圆点只有 30px | 圆点视觉放大到 34px，另用透明伪元素 `inset:-8px` 把**可点区域**撑到 50px（直接画成 44px 会让十几个地点在澳门糊成一片） |
| 地图角标被收起态面板压住 | 图例、比例尺、署名都在 `bottom:10~16px` | 用 `--panel-peek` 把它们抬到面板上方 |
| 横屏列表完全看不到 | 左栏只有 320px 高，固定块就有 400px | 用 flex `order` 把摘要与底栏在视觉上挪到列表后面（DOM 不动），整栏滚动 |

还顺手加了：抓握条（提示可收起）、标题栏吸顶（滚下去也能收起）、安全区留白（`env(safe-area-inset-*)`）。

### 其他

- **减少动效开关**：关闭所有过渡动画，尊重 `prefers-reduced-motion`
- **响应式**：三个布局，同一个 980px 宽度阈值分叉——宽屏三栏 / 竖屏底部抽屉 / 横屏左列表右详情
- **无障碍**：地图信息有列表替代视图；标记带 `aria-label`；正文对比度达标

## 数据来源与可信度

**这一节很重要——原型里的数据不是随便编的。**

| 字段 | 来源 | 可信度 |
|---|---|---|
| 地点清单 | 用户提供的小红书笔记链接（**7 条**，逐条解析） | 与笔记一致 |
| 正文 / 推荐菜 / 描述 | 笔记正文 + 配图，CDP 直连 `__INITIAL_STATE__` 提取 | 与笔记一致 |
| **配图** | 各笔记的 `imageList`，裁切压缩后落在 `assets/places/<id>/` | 原图，非二次创作 |
| 地址 / 营业时间 / 电话 / 价格 / 出炉时间 | **笔记里的门店照片与菜单照片**，或店家官网 / 商户名录 | 逐条在 `hoursFrom` 标注，⚠️ 未全部二次核对 |
| 坐标 | `photon.komoot.io`（OSM 数据），按楼名 / 街道名检索 | 楼宇级 or 街道级，逐条标注 |
| 门牌反查 | `webmap.gis.gov.mo` 街道门牌查询系统 | 用于把「看台街 198 号」解析成「信託花園银成阁」 |
| 建议停留时长 / 时段 | 编辑整理，按营业时间倒推 | **示例编排，需人工核实** |

**坐标精度逐条标注**（字段 `coordNote`，会显示在详情卡里）：

| 地点 | 精度 | 说明 |
|---|---|---|
| 好利是咖啡小食 | ⚠️ **街道级，±60m** | 店未登记在 OSM，用祐汉新村第四街定位；门牌 29 号未能在街景照片中确认 |
| 十月初五馬路 | ⚠️ **街道级，±80m** | 取街道中段坐标，全长约 600m |
| 其余 11 处 | ✅ 楼宇级，高置信 | 已解析到具体楼宇（如 `Edifício Tak Fu` 德富大廈、`Pek Iun` 碧苑） |

**配图说明**：20 张图全部来自对应笔记的实拍照片，`cap` 字段写清拍的是什么。
**笔记没拍到地点本体时，说明里会写明**——例如路環圖書館用的是它所在街区的街景，
文案直接写「笔记未单拍图书馆本体，这张是它所在的教堂前地一带街景」，不拿相近照片冒充。
薈真集那条笔记本身只有 1 张配图，所以该地点只有 1 张。

**已知的数据问题**：

1. **营业时间 / 电话 / 价格部分来自笔记照片**，可能与现况不符。伙牛的电话在照片里只能看清前 6 位（`2822 30xx`）。
2. 好利是的坐标只有街道级精度，门牌号未经实地确认。
3. **第 4 个地点的小红书短链（`xhslink.cn/o/0wxBHPZAmh`）返回 404**，已请用户重发，尚未入库（原计划是祐汉一带的 6 处，现为 5 处）。
4. **鐵餅號周一店休**——若行程落在周一，这一站要跳过，13:00–13:20 的空档需重排。
5. **拱北口岸的通关时间（06:00 – 次日 01:00）来自第三方攻略站**（珠海本地宝、澳门114，两处一致），
   **没有查到口岸官方发布**。赶早过关前建议再确认一次。另外它是本次唯一没有配图的地点。
6. **正式上线前，所有营业信息必须人工核实并标注核实日期**（见 [`02-产品设计方案.md`](./02-产品设计方案.md) 的「内容与资料来源规范」）。

## 文件结构

站点文件全部在**仓库根目录**（不再是 `app/` 子目录）：


### 数据与渲染是解耦的

`app.js` 里**没有任何城市名、天数、地点数量的硬编码**。换城市只需改 `data/places.js`。

数据规整全部集中在 `normalize()` 一个函数里（`app.js` 第 49–138 行附近），它负责：

1. 补 `CITY` 默认值，`en` 缺失时从 `name` 派生
2. `DAYS` 缺失时按地点里出现的最大 `day` 推算，颜色从 `DAY_PALETTE`（10 色）循环取
3. 补地点字段默认值；缺经纬度的地点置 0,0 并 `console.warn`
4. 按 `order` 排序并重编 `badge`（`1-1`、`1-2`…）
5. `CITY.center` 缺失时用地点的包围盒中心
6. `TRIP` 统计（地点数 / 天数 / 餐饮数 / 建议停留）现算，避免与真实数据不一致

**验证方式**：用一个只有「地点名 + 经纬度 + 第几天」的 12 地点京都数据替换 `places.js`，
页面仍完整渲染——标题变「京都旅行工作台」、徽章变两位数、缺失字段优雅留空。

`data/places.js` 是**手工整理的**（见文件头注释），正式版应改为后端接口。

## 技术要点（踩过的坑）

1. **MapLibre 的 `load` 事件依赖首帧渲染完成**。在后台标签页里 `requestAnimationFrame` 被 Chrome 节流，`load` 永不触发，地图一片空白。改用 `style.load`（样式解析完就触发，不依赖渲染）。
2. **矢量瓦片只在渲染帧里才会被请求**。所以「后台标签页里地图空白」是假象——不是代码问题。调试地图时务必在前台窗口看。
3. **无头浏览器里 WebGL 需要额外开关**。只加 `--disable-gpu` 会让 WebGL 初始化失败（`Could not create a WebGL context`），必须用 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`。这一点也促成了一处**真实加固**：`new maplibregl.Map()` 现在包在 try/catch 里，失败时显示降级提示而不是整块空白。
4. **CSS `display:flex` 会覆盖 `[hidden]` 属性**。已统一加 `[hidden]{display:none !important}`。
5. **虚线动画不要用 Mapbox 官方示例的 `[0,4,3]` 序列**——它会让虚线在某些相位几乎消失。改用「dash/gap 恒定 + 相位平移」的 4 元素数组写法。
6. **`CITY.zoom` 不等于运行期 `map.getZoom()`**。`style.load` 后会用 `fitBounds` 把视野收紧到刚好装下所有标记，所以实测 zoom 通常是 14 而不是配置里的 13.6。这是设计如此。
7. **`position:sticky` 是「悬浮在可滚动栏里」的正解**，比 `position:absolute` 好——后者会跟着内容一起滚走。关闭按钮外层用 `height:0` 包裹，这样 sticky 生效又不占位。
8. **列表里别直接用大图当缩略图**。42px 的坑位配 900px 的原图，13 行就是 2.6 MB。改成同目录 `thumb.jpg`（180px）后降到 96 KB。缩略图总量这么小，就不必惰性加载了——`loading="lazy"` 反而会在合成滚动场景里出现「滚动后仍有几行不加载」的观感问题。
9. **`overflow-x:auto` 会把元素变成滚动容器，而 flex 的「自动最小尺寸」对滚动容器是 0**。所以 `.daytabs` 加上横滑之后，一旦面板内容超高，它就被压成一条 12px 的线——不是布局算错，是规范如此。要么显式 `flex:0 0 auto`，要么别让它当 flex item。
10. **`100vh` 在移动端不等于可视高度**。地址栏会收放，`100vh` 取的是「地址栏收起时」的高度。用 `100dvh`（带 `100vh` 兜底）才能跟着变。前提是页面别用 body 滚动——`html/body{height:100%}` + 一个 `overflow:auto` 的主区，比「body 自然滚动 + sticky 顶栏」在移动端稳。
11. **标准 `line-clamp` 会改写 `display`**。写了 `line-clamp:2` 之后，`display:-webkit-box` 会被换成 `flow-root`，反倒让 `-webkit-line-clamp` 那套失效。两个别混着写；只写 `-webkit-line-clamp` 就够（Chrome / Safari / Firefox 都支持）。
12. **无头 Chrome 会复用同一个 profile 的 HTTP 缓存**。改完 CSS/JS 再跑测试，可能拿到的还是上一版——现象是「改动没生效」，非常容易误判成代码问题。测试脚本里必须 `Network.setCacheDisabled`。同理，`Page.navigate` 到**只差 hash 的同一个 URL 不会重载页面**，多设备连测时状态会从上一台串过来，要先跳 `about:blank` 或用带随机查询串的 URL。
13. **`python -m http.server` 下 `naturalWidth` 偶发为 0，是测试假阳性，不是图坏了**。它回的是 `HTTP/1.0`（每次响应后关连接），13 张缩略图 + 20 张详情图 + 地图瓦片一起并发时，个别图片会慢到断言跑完还没解码——于是出现 `complete=true` 但 `naturalWidth=0` 这种「看起来像坏图」的组合。**判据是三条一起看**：`file` 能认出 JPEG、`curl` 取回的字节 md5 与磁盘一致、`sips` 能读出像素尺寸。三条都过就是时序问题，修法是断言前轮询就绪或多等一拍，别去改代码。
14. **并行跑多个无头 Chrome 实例会互相拖慢，固定 `sleep` 等页面就绪不可靠**。同一台机器上并行跑桌面回归 + 移动端截图 + 排序测量时，CPU 被 swiftshader 软件渲染吃满，原本 9 秒能渲染完的页面可能十几秒还没跑 JS——现象是「选择器全都取不到值」，很容易误判成应用挂了。改成**轮询就绪条件**（例如等 `.place-row` 数量到位）再断言。另外 `Page.captureScreenshot` 在负载高时可能几十秒不回，CDP 调用要给足超时。
15. **核心渲染库别挂在单一 CDN 上**。`cdn.jsdelivr.net` 抽风时（本机实测 `curl` 返回 000，而瓦片源 `tiles.openfreemap.org` 返回 200），`index.html` 的 `<script src>` 拿不到 MapLibre，地图区直接变成「地图库未能加载」——**看起来像地图代码坏了，其实只是那个 CDN 不通**。排查方式是分别测「库的 CDN」和「瓦片源」两条链路。零构建站点把这类库落到 `vendor/` 更稳，也才对得起「clone 下来就是完整应用」这句话。
