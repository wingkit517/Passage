## 已实现（对照设计文档）

### 地图工作台

- **倾斜鸟瞰视角**：pitch 50°、bearing -12°，城市尺度下能看到立体感
- **3D 建筑**：直接用 OpenFreeMap liberty 样式自带的 `building-3d` 挤出图层（依赖瓦片里的 `render_height` 字段，zoom ≥ 14 生效）
- **编号标记**：横向椭圆（v1.5）—— `1-1`…`1-3` + `2-1`…`2-14`，宽度随编号长度走，按天着色。
  原来是固定 30px 圆，两位数会被硬塞要靠 `.is-long` 收字号；改成 `border-radius:50%` + `padding:0 8px` + `min-width:28px`
  后两位数自然横展
- **标记避让**：城市尺度下地点会挤在一起，用一次屏幕空间松弛迭代把重叠标记推开。
  椭圆的 SPREAD_MIN 提到 44px（贴 `2-14` 的实际宽度 46.5px 取整），SPREAD_MAXOFF 提到 28px；
  同时把 `spreadMarkers` 绑到 `moveend`，让纯平移与「缩放不变只 fitAll」的情况也会重排（`zoomend` 在这两种场景下不触发）
- **路线虚线**：每个有 ≥2 个坐标的日期一条 GeoJSON 折线（v1.5 加了对单地点日期的防御，不建非法 1 点 LineString），白色描边 + 彩色虚线，带相位平移的「流动」动画
- **镜头飞近**：点击地点 → `flyTo` zoom 16.2 / pitch 55°，1200ms 缓动
- **三栏联动**：日期 Tab、类型筛选、地点列表、地图、详情卡全部同步
  （天数 ≥2 时才渲染日期 Tab；半天日期的路线与排序都有专门的退化文案，见下面「v1.5 退化保护」）
- **降级处理**：WebGL 创建失败或底图加载失败时显示提示条，左侧列表与右侧详情仍可用

### 路线自动排序（v1.1 新增）

面板顶部三个控件：**自动排序 / 撤销 / 起点锁定**。

- **最近邻 + 2-opt**：haversine 距离 → 最近邻生成初始解 → 2-opt 消除交叉路径
- **建议性，不自动生效**：排序后显示收益，用户看得到再决定留不留。**实测（v1.5 当前数据集，17 处跨两天）**：

  | | 排序前 | 锁定起点 | 放开起点 |
  |---|---|---|---|
  | 全天（17 处，拱北口岸 → 半岛 → 路环 → 氹仔 → 第 2 天） | 28.7 km | 23.1 km（省 5.5 km，−19.3%） | **23.1 km（省 5.5 km，−19.3%）** |

  两点值得记下来：

  1. **跨两天后收益相对值变小了**（−26.5% → −19.3%），但**绝对值一样省了 5.5 km**。
     拱北口岸在地理上就是全程最北端的地点，纯距离最优也会从它出发——
     所以「起点锁定」在当前数据上不损失任何收益。
     它防的是另一种情况：**首站被硬性指定、但它不在地理端点**（例如必须从酒店出发，而酒店在路线中段）。
  2. **−19.3% 看起来大，但别误读**。这个数省下来的主要是**半岛内部的折返**，不是「少跑一趟路环」——
     拱北 → 半岛 → 路环 → 氹仔 的单向走法在两种顺序里都躲不掉。手工顺序是照营业时间排的
     （薈真集 10:30 才开、鐵餅號 12:00 才开），代价就是半岛内部来回。所以这 5.5 km 是
     「时间约束换来的距离」，不是排错了。

  > 距离口径：地点之间的 **haversine 直线距离**之和，不是步行 / 公交实际里程，也不是耗时。只用来比较两种顺序的相对长短。
- **半天日期不会算空**：< 3 个地点的一天，2-opt 没有可优化的折返，给出「可排序的地点少于 3 处，没有可优化的折返」而非「已经是最短的」——后者会让用户以为算过。
- **一键撤销**：快照存在 `sortSnapshot`，还原到排序前
- **起点锁定（默认开）**：每天第一站（口岸 / 酒店 / 早餐店）不被移动
- **无收益时不动作**：若已是最短，提示「当前顺序已经是最短的，没有可优化的折返」，且不显示撤销按钮
- **免责提示**：文案里明确写「只优化距离，不考虑「把某处留到夜里」这类编排意图」

> **为什么排序不自动生效**：参照笔记的 Day 1 手工顺序是 `新天地 → 豫园 → 外滩 → 北外滩 → 陆家嘴`，
> 末段刻意绕到北外滩是为了**过江看夜景**。纯距离最优会把它反过来——**「总距离最短」是错的优化目标**。
>
> 当前澳门数据里也有同一个道理：黑沙海灘被排在 18:25 到，是为了看日落（代价是天色已暗）。
> 纯距离最优会把它往前提。详见 [`03-技术实现方案.md`](./03-技术实现方案.md) §4.2。

### 「数据与渲染解耦」的三次兑现

同一个原则：**app.js 不存任何城市名 / 天数 / 地点数 / 产品名**，只对结构负责；改完数据自然就成了新行程。
下面是从 v1.2 → v1.5 的三个真实例子。

**① v1.3 · 两天并成一天**：用户要求把原「第 1 天半岛 / 第 2 天路环」压成一天，数据侧 `DAYS` 从 2 条减到 1 条 + 14 处 `day` 全部置 `0`，
`app.js` 一行没动——路线 `DAYS.forEach` 自动只剩 `route-0`，编号 `renumber()` 自动从 `1-1`…`1-13` 重排为 `1-1`…`1-14`。
**但文案会露馅**：「逐天看」「点一天」「全部 1 天」这种说法只在两天以上才自然，于是所有天数相关文案都跟着 `DAYS.length` 走：

| 位置 | 多天时 | 单天时 |
|---|---|---|
| 顶部副标题 | `MACAU · 2 日行程` | `MACAU · 1 日行程` |
| 总览小标题 | 「这 2 天怎么走」 | 「这一天怎么走」 |
| 面板副标题 | 「点一天，看当天的路线」 | 「按时间顺序串成一条线」 |
| 天数标签行 | 总览 / 第 1 天 / 第 2 天 | **整行不显示** |
| 排序作用域提示 | 「全部 2 天」 | 「第 1 天」（而不是「全部 1 天」） |

天数标签行整行隐藏的理由很直接：「总览」与「第 1 天」在只有一天时内容完全一样，留着只是让人多点一次。

**合并的代价要如实写出来**：黑沙海灘现在 18:25 到，而 9 月下旬澳门日落约 18:20——**看到的是暮色里的海滩，
不是原笔记那种大白天**。这一条同时写进了 `data/places.js` 的 `hac-sa.desc` 与 [`04-行程清单-中山与澳门.md`](./04-行程清单-中山与澳门.md) 的 ⚠️ 提示，没有藏起来。

**② v1.4 · 拱北口岸作为跨城起点**：用户指定「我们从拱北口岸出发」，新增一处珠海侧口岸。
**性质完全不同**——跨城、非笔记来源、无配图、新分类（交通）。三处改动：

| 差异 | 处理 |
|---|---|
| 珠海侧 | 数据显式标 `cat: "交通"`，成第 5 个筛选大类。**不用改 app.js**——`ALL_TYPES` 本来就会把 `CAT_ORDER` 之外的分类追加到末尾 |
| 非笔记来源 | 详情卡底部的「内容来源」原本写死成「用户提供的小红书笔记」，加可选的 **`srcNote`** 字段：给了就用数据的，没给仍走默认 |
| 无配图 | 不需要改代码：`normalize()` 里 `p.thumb` 从 `imgs[0]` 推出，没有 `imgs` 就是空串，列表行直接不渲染缩略图 |

编号照旧由 `renumber()` 算出 `1-1`…`1-14`，其余 13 处自动后移一位。
**`app.js` 只动了 2 行**（`srcNote` 的读取与默认值列表）。

**③ v1.5 · 把一天的澳门拆成「中山 + 澳门」两天**：详见下一节。

### 两天结构（v1.5 新增）

把原 1 天 14 处澳门拆成「第 1 天 · 中山（3 处）」+「第 2 天 · 澳门（14 处）」，并补上产品名 **Passage**。
比 ② 更进一步——同时跨城、跨天、加起点、改产品名。

**① `CITY` 不再单指澳门**。`name` 改为 `"中山 · 澳门"`、`en` 改为 `"ZHONGSHAN · MACAU"`、`center` 故意留 `null` 交给 `normalize()` 按全部地点的包围盒现算（中山站 22.548N ↔ 澳门黑沙 22.116N，南北跨度约 48km，写死一个中心点等加新地点就过期了）。`TRIP.title` 改成 `"中山 · 澳门 · 两日行程"`、`dayCount` 设 2。

**② `DAYS` 拆成两天**。第 1 天蓝色 `#2C4A8F`、第 2 天继续沿用澳门原色 `#C0392B`，与历史截图保持视觉一致。

**③ 14 处澳门 `day` 全部翻到 1**，新增 3 处中山：中山站（用户指定，OSM 节点，18:00 出发）/ 松本寿司（笔记解析，10:30–20:00）/ 圆宝阿公（笔记解析，13:00 起叫号）。`renumber()` 自动算出 `1-1…1-3` + `2-1…2-14`。

**④ `APP.name = "Passage"`**。`app.js` 里把所有露出的品牌字样（`document.title` / 顶栏 `brandMark` / console.warn 前缀）都从 `D.APP.name` 取；改一处换名，不散落硬编码。

**⑤ `app.js` 跟着做的调整**：
- `brandSub` 不再说 `ONE CITY`（跨城行程下会撒谎），改成 `c.en + ' · ' + PLACES.length + ' PLACES' + (DAYS.length > 1 ? ', ' + DAYS.length + ' DAYS' : '')`
- `hhSub` 不再写死「上午澳门半岛、下午路环岛」（城市与片区由数据决定），改成纯结构描述
- `renderChrome()` 的天数相关文案继续按 `oneDay` 走（v1.3 那张表原样复用）

`index.html` 的静态 `<title>` 与 `brandMark` 初始占位也改成 "Passage"，被 `app.js` 启动时立刻覆盖。

### 退化保护（v1.5 新增）

v1.5 加中山那天之后，**理论上会出现只有 1 个地点的日期**——比如用户删中山第 1 天的两个地方、就剩中山站。
那天会产生两个坑：

**坑 ① 1 点 LineString**：GeoJSON 规范要求 `LineString` 至少 2 个坐标。
实测（MapLibre GL JS 5.24）：塞 1 个坐标**不会抛错**，图层照样建起来，只是渲染时没有任何输出——即「不报错的静默失败」，比抛错还难排查。
所以 `addRoutes()` 里先 `if (routeCoords(d.index).length < 2) return;`，半天日期就不建路线图层。

**坑 ② 1 点 fitBounds**：包围盒退化成「一个点」、宽高都是 0。
实测：`fitBounds` 在 `maxZoom: 14` 下能正常把缩放顶到 14、中心落在该点——结果与下面这段显式 `easeTo` 完全一致。
但这个正确结果依赖 `maxZoom` 恰好设了 14、以及 MapLibre 肯把内部 `Infinity` 一路算下去，所以仍然写明：

```js
if (pts.length === 1) {
  map.easeTo({ center: [pts[0].lng, pts[0].lat], zoom: 14, pitch: CITY.pitch,
               bearing: CITY.bearing, duration: state.reduceMotion ? 0 : 900 });
  return;
}
```

**坑 ③ `autoSort` 对半天日期**：原代码会把 `< 3` 个点的日期跳过但仍报「当前顺序已经是最短的」，让用户以为算过。
改成给一个专门的提示 `可排序的地点少于 3 处，没有可优化的折返`，并在 `sortSnapshot = null` 不留撤销按钮。

### 调试句柄（v1.5 新增）

`window.PASSAGE` 是只读调试句柄，给无头 Chrome + CDP 验证脚本用：

```js
window.PASSAGE = {
  map: function () { return map; },     // 地图实例
  data: D,                              // 规整后的数据
  state: state,                         // 当前视图状态
  days: function () { return DAYS; },
  places: function () { return PLACES; },
  routeLayer: function (i) {            // 'no-map' | 'missing'（没建） | 'visible' | 'none'（隐藏）
    if (!map) return 'no-map';
    var id = 'route-' + i + '-line';
    if (!map.getLayer(id)) return 'missing';
    return map.getLayoutProperty(id, 'visibility') || 'visible';
  }
};
```

之前验证脚本只能从 DOM 反推（`.place-row` 数行、`/.*/.test(textContent)`、标记数量），
地图实例与 `DAYS/PLACES` 都在 IIFE 闭包里、拿不到——加了半天 / 退化保护之后要确认「`routeLayer(0)` 是否真的 `missing`」
就只能靠这个句柄。**全是取值函数 / 数据，不暴露任何写入口，也不参与业务逻辑**。

### 横向椭圆编号标记（v1.5 新增）

用户反馈两位数编号（如 `2-14`）在原来的 30×30 固定圆里被硬塞，只能靠 `.is-long` 缩字号。
改成胶囊形（其实是 `border-radius:50%` 配非正方形宽高 → 真椭圆）：

```css
.place-badge{
  height:28px; min-width:28px; padding:0 8px;
  border-radius:50%;   /* 椭圆的关键：非正方形宽高 */
  ...
}
```

实测尺寸：

| 编号 | 字符数 | 宽 × 高 (px) |
|---|---|---|
| `1-1`（最短） | 3 | 34.1 × 24 |
| `2-6` | 4 | 39.9 × 28 |
| `2-14`（最长） | 5 | 46.5 × 28 |

字号不再按编号长度分档，**所有徽章都 11px**。同步把 `SPREAD_MIN` 从 34 提到 44（贴 `2-14` 实际宽度取整）、
`SPREAD_MAXOFF` 从 24 提到 28，并把 `spreadMarkers()` 绑到 `moveend`——这样 `fitBounds` 后（`zoom` 不变的情况）也会重排，
`zoomend` 不触发、`moveend` 触发。

附带清理：`is-long` 这个 class 在 `place-badge` 上不再有 CSS 效果（只有列表里的 `.pr-badge` 仍在用，逻辑不变），
js 里也不再给它加 class。

### 移动端适配（v1.3 新增）

手机上用的是**底部抽屉**：行程面板默认收起成一条（只露标题栏），点标题栏展开；地点详情是更靠前的一层浮层。
横屏（矮屏 + 够宽）换成**左列表 + 右详情**——390px 高的视口里，底部抽屉会把地图压成一条缝。

这一轮修掉的问题，全部是先用脚本量出来的，不是靠肉眼估：

| 问题 | 原因 | 处理 |
|---|---|---|
| 地图底部溢出视口 24px | `#view-map{height:calc(100vh - 57px)}` 里的 57px 是桌面端顶栏高度；窄屏顶栏换行后是 81px | 拆掉写死的数字，改成 `body` 纵向 flex + `#main{flex:1}`，地图高度由剩余空间算出来；同时用 `100dvh` 让地址栏收放时也跟着变 |
| 收起态面板把页面顶出滚动条（文档高 1040 vs 视口 667） | 收起用 `transform:translateY(calc(100% - 152px))` 往下平移，整块被推出视口 | 改成收缩 `max-height`（面板自身 `overflow-y:auto`），不再平移 |
| 收起后露出的高度对不上 | 152px 是写死的，标题换行就错位 | `app.js` 实测标题栏高度写进 `--panel-peek`，CSS 用它 |
| 展开后地点列表只剩几十像素 | 面板内固定块（标题栏+天数+排序+摘要+筛选+底栏）加起来超过面板高度，列表被压成 0 | 面板整体滚动而不是只让列表滚；摘要里的地点串裁成一行；天数与筛选改单行横滑 |
| 天数标签被挤成一条线 | `.daytabs` 加了 `overflow-x:auto` 后成了滚动容器，而 flex 的「自动最小尺寸」对滚动容器是 **0** | 显式 `flex:0 0 auto` |
| 触控目标普遍偏小 | `.nav-btn` 30px、`.daytab` 31px、`.chip` 24px、`.btn-sm` 29px、MapLibre 控件 29px | 窄屏统一抬到 ≥44px（Apple HIG / Material 下限） |
| 地图标记点不中 | 圆点只有 30px | v1.4 圆点视觉放大到 34px；v1.5 改成横向椭圆（高度 28/32px，宽随编号长度 34–46px），同样用透明伪元素 `inset:-8px` 把**可点区域**撑到 ≥44px（直接画成 44px 会让十几个地点在澳门糊成一片） |
| 地图角标被收起态面板压住 | 图例、比例尺、署名都在 `bottom:10~16px` | 用 `--panel-peek` 把它们抬到面板上方 |
| 横屏列表完全看不到 | 左栏只有 320px 高，固定块就有 400px | 用 flex `order` 把摘要与底栏在视觉上挪到列表后面（DOM 不动），整栏滚动 |

## 文件结构

站点文件全部在**仓库根目录**（不再是 `app/` 子目录）：

```
<仓库根>/
├── index.html          # 两个视图的骨架
├── styles.css          # 全部样式（纸张底 + 每日主题色）
├── app.js              # 核心逻辑：数据规整 / 视图切换 / 地图 / 面板 / 详情 / 排序

│   └── places.js       # 数据层：CITY + TRIP + DAYS + PLACES
├── assets/
│   └── places/<id>/    # 每处地点：1.jpg 2.jpg（长边 900px）+ thumb.jpg（180px）
└── vendor/
    └── maplibre/       # 内置的 MapLibre GL JS 5.24.0（js + css + LICENSE.txt，BSD-3-Clause）
```

这样 clone 下来起一个静态服务就是完整应用，也能直接挂 GitHub Pages。

> **为什么把地图库放进仓库**（v1.4）：原本从 `cdn.jsdelivr.net` 引入，2026-09-27 那次
> jsdelivr 在本机不可达（`curl` 返回 000，而瓦片源 `tiles.openfreemap.org` 正常 200），
> 结果**整块地图变成「地图库未能加载」**。一个号称「clone 下来就是完整应用」的零构建站点，
> 不该把核心渲染库挂在单一 CDN 上。落到本地后，1.03 MB 的代价换掉了这个单点故障。

### 数据与渲染是解耦的

`app.js` 里**没有任何城市名、天数、地点数量的硬编码**。换城市只需改 `data/places.js`。

数据规整全部集中在 `normalize()` 一个函数里（`app.js` 第 49–138 行附近），它负责：

1. 补 `CITY` 默认值，`en` 缺失时从 `name` 派生
2. `DAYS` 缺失时按地点里出现的最大 `day` 推算，颜色从 `DAY_PALETTE`（10 色）循环取
3. 补地点字段默认值；缺经纬度的地点置 0,0 并 `console.warn`
4. 按 `order` 排序并重编 `badge`（`1-1`、`1-2`…）
5. `CITY.center` 缺失时用地点的包围盒中心
6. `TRIP` 统计（地点数 / 天数 / 餐饮数 / 建议停留）现算，避免与真实数据不一致

**验证方式**：用一个只有「地点名 + 经纬度 + 第几天」的 12 地点京都数据替换 `places.js`，
页面仍完整渲染——标题变「京都旅行工作台」、徽章变两位数、缺失字段优雅留空。

`data/places.js` 是**手工整理的**（见文件头注释），正式版应改为后端接口。

## 技术要点（踩过的坑）

1. **MapLibre 的 `load` 事件依赖首帧渲染完成**。在后台标签页里 `requestAnimationFrame` 被 Chrome 节流，`load` 永不触发，地图一片空白。改用 `style.load`（样式解析完就触发，不依赖渲染）。
2. **矢量瓦片只在渲染帧里才会被请求**。所以「后台标签页里地图空白」是假象——不是代码问题。调试地图时务必在前台窗口看。
3. **无头浏览器里 WebGL 需要额外开关**。只加 `--disable-gpu` 会让 WebGL 初始化失败（`Could not create a WebGL context`），必须用 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`。这一点也促成了一处**真实加固**：`new maplibregl.Map()` 现在包在 try/catch 里，失败时显示降级提示而不是整块空白。
4. **CSS `display:flex` 会覆盖 `[hidden]` 属性**。已统一加 `[hidden]{display:none !important}`。
5. **虚线动画不要用 Mapbox 官方示例的 `[0,4,3]` 序列**——它会让虚线在某些相位几乎消失。改用「dash/gap 恒定 + 相位平移」的 4 元素数组写法。
6. **`CITY.zoom` 不等于运行期 `map.getZoom()`**。`style.load` 后会用 `fitBounds` 把视野收紧到刚好装下所有标记，所以实测 zoom 通常是 14 而不是配置里的 13.6。这是设计如此。
7. **`position:sticky` 是「悬浮在可滚动栏里」的正解**，比 `position:absolute` 好——后者会跟着内容一起滚走。关闭按钮外层用 `height:0` 包裹，这样 sticky 生效又不占位。
8. **列表里别直接用大图当缩略图**。42px 的坑位配 900px 的原图，15 行就是 3.1 MB。改成同目录 `thumb.jpg`（180px）后降到 ~110 KB。缩略图总量这么小，就不必惰性加载了——`loading="lazy"` 反而会在合成滚动场景里出现「滚动后仍有几行不加载」的观感问题。
9. **`overflow-x:auto` 会把元素变成滚动容器，而 flex 的「自动最小尺寸」对滚动容器是 0**。所以 `.daytabs` 加上横滑之后，一旦面板内容超高，它就被压成一条 12px 的线——不是布局算错，是规范如此。要么显式 `flex:0 0 auto`，要么别让它当 flex item。
10. **`100vh` 在移动端不等于可视高度**。地址栏会收放，`100vh` 取的是「地址栏收起时」的高度。用 `100dvh`（带 `100vh` 兜底）才能跟着变。前提是页面别用 body 滚动——`html/body{height:100%}` + 一个 `overflow:auto` 的主区，比「body 自然滚动 + sticky 顶栏」在移动端稳。
11. **标准 `line-clamp` 会改写 `display`**。写了 `line-clamp:2` 之后，`display:-webkit-box` 会被换成 `flow-root`，反倒让 `-webkit-line-clamp` 那套失效。两个别混着写；只写 `-webkit-line-clamp` 就够（Chrome / Safari / Firefox 都支持）。
12. **无头 Chrome 会复用同一个 profile 的 HTTP 缓存**。改完 CSS/JS 再跑测试，可能拿到的还是上一版——现象是「改动没生效」，非常容易误判成代码问题。测试脚本里必须 `Network.setCacheDisabled`。同理，`Page.navigate` 到**只差 hash 的同一个 URL 不会重载页面**，多设备连测时状态会从上一台串过来，要先跳 `about:blank` 或用带随机查询串的 URL。
13. **`python -m http.server` 下 `naturalWidth` 偶发为 0，是测试假阳性，不是图坏了**。它回的是 `HTTP/1.0`（每次响应后关连接），13 张缩略图 + 20 张详情图 + 地图瓦片一起并发时，个别图片会慢到断言跑完还没解码——于是出现 `complete=true` 但 `naturalWidth=0` 这种「看起来像坏图」的组合。**判据是三条一起看**：`file` 能认出 JPEG、`curl` 取回的字节 md5 与磁盘一致、`sips` 能读出像素尺寸。三条都过就是时序问题，修法是断言前轮询就绪或多等一拍，别去改代码。
14. **并行跑多个无头 Chrome 实例会互相拖慢，固定 `sleep` 等页面就绪不可靠**。同一台机器上并行跑桌面回归 + 移动端截图 + 排序测量时，CPU 被 swiftshader 软件渲染吃满，原本 9 秒能渲染完的页面可能十几秒还没跑 JS——现象是「选择器全都取不到值」，很容易误判成应用挂了。改成**轮询就绪条件**（例如等 `.place-row` 数量到位）再断言。另外 `Page.captureScreenshot` 在负载高时可能几十秒不回，CDP 调用要给足超时。
15. **核心渲染库别挂在单一 CDN 上**。`cdn.jsdelivr.net` 抽风时（本机实测 `curl` 返回 000，而瓦片源 `tiles.openfreemap.org` 返回 200），`index.html` 的 `<script src>` 拿不到 MapLibre，地图区直接变成「地图库未能加载」——**看起来像地图代码坏了，其实只是那个 CDN 不通**。排查方式是分别测「库的 CDN」和「瓦片源」两条链路。零构建站点把这类库落到 `vendor/` 更稳，也才对得起「clone 下来就是完整应用」这句话。
