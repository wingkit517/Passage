### 路线自动排序（v1.1 新增）

面板顶部三个控件：**自动排序 / 撤销 / 起点锁定**。

- **最近邻 + 2-opt**：haversine 距离 → 最近邻生成初始解 → 2-opt 消除交叉路径
- **建议性，不自动生效**：排序后显示收益，用户看得到再决定留不留。**实测（v1.5 当前数据集，17 处跨两天）**：

  | | 排序前 | 锁定起点 | 放开起点 |
  |---|---|---|---|
  | 全天（17 处，拱北口岸 → 半岛 → 路环 → 氹仔 → 第 2 天） | 28.7 km | 23.1 km（省 5.5 km，−19.3%） | **23.1 km（省 5.5 km，−19.3%）** |

  两点值得记下来：

  1. **跨两天后收益相对值变小了**（−26.5% → −19.3%），但**绝对值一样省了 5.5 km**。
     拱北口岸在地理上就是全程最北端的地点，纯距离最优也会从它出发——
     所以「起点锁定」在当前数据上不损失任何收益。
     它防的是另一种情况：**首站被硬性指定、但它不在地理端点**（例如必须从酒店出发，而酒店在路线中段）。
  2. **−19.3% 看起来大，但别误读**。这个数省下来的主要是**半岛内部的折返**，不是「少跑一趟路环」——
     拱北 → 半岛 → 路环 → 氹仔 的单向走法在两种顺序里都躲不掉。手工顺序是照营业时间排的
     （薈真集 10:30 才开、鐵餅號 12:00 才开），代价就是半岛内部来回。所以这 5.5 km 是
     「时间约束换来的距离」，不是排错了。

  > 距离口径：地点之间的 **haversine 直线距离**之和，不是步行 / 公交实际里程，也不是耗时。只用来比较两种顺序的相对长短。
- **半天日期不会算空**：< 3 个地点的一天，2-opt 没有可优化的折返，给出「可排序的地点少于 3 处，没有可优化的折返」而非「已经是最短的」——后者会让用户以为算过。
- **一键撤销**：快照存在 `sortSnapshot`，还原到排序前
- **起点锁定（默认开）**：每天第一站（口岸 / 酒店 / 早餐店）不被移动
- **无收益时不动作**：若已是最短，提示「当前顺序已经是最短的，没有可优化的折返」，且不显示撤销按钮
- **免责提示**：文案里明确写「只优化距离，不考虑「把某处留到夜里」这类编排意图」

> **为什么排序不自动生效**：参照笔记的 Day 1 手工顺序是 `新天地 → 豫园 → 外滩 → 北外滩 → 陆家嘴`，
> 末段刻意绕到北外滩是为了**过江看夜景**。纯距离最优会把它反过来——**「总距离最短」是错的优化目标**。
>
> 当前澳门数据里也有同一个道理：黑沙海灘被排在 18:25 到，是为了看日落（代价是天色已暗）。
> 纯距离最优会把它往前提。详见 [`Passage_2d 技术方案与质量门槛.md`](./Passage_2d 技术方案与质量门槛.md) §4.2。

### 行程时间调整（v1.6 新增）

入口三处：**出发时刻**（面板时间调整条，仅单天视图）· **停留时长 −/＋**（详情卡信息块，±5 分钟）· **还原这天**（调整过才显示）。

- **衔接语义**：站间「衔接分钟 = 原计划间隔」（下一站到达 − 本站离开），顺延 = 上一站离开 + 衔接。
  这个间隔大多是路程时间，个别是「等开门」的空档（薈真集那 2 小时），所以另有开门钳制兜底：
  **到达不早于开门时间**——提前出发会被钳到开门并打「等开门 hh:mm」标记（实测：第 2 天改 05:30 出发，
  口岸钳到 06:00、好利是钳到 07:00、薈真集钳到 10:30，钳制把提前量全部吸收，伙牛起与原计划重合）。
- **超打烊警告**：营业时间写法规整（开头即 `HH:MM[–HH:MM]`）才解析出开门/打烊；解析不出（圆宝阿公打烊未核、
  海滩全天开放）就不参与判断——未核实就是未核实。跨午夜打烊（糖朝 15:00–01:30）当天不可能超，不设。
- **clock 由 duration 重串**：调整后时刻字符串按 `duration` 重新生成（range / point 两种格式，「18:00 出发」的后缀原样保留）。
  天跨度（`DAYS.span` 的时刻前缀）与行程级 stayHours 同步现算，主题尾注不动。
- **与排序联动**：自动排序改变相邻关系后，衔接分钟按「原计划出现过的相邻对（含反向）沿用原值、新对按直线距离粗估
  （≤1.2km 步行 4.5km/h + 2min，更远车程 25km/h + 8min，**仅为串时刻的估算**）」重算并重串时刻；
  撤销排序后原计划相邻对原样找回，**实测时刻逐站复原、零偏差**。
- **还原这天**：只回退出发时刻与各站停留，不动顺序（撤销排序管顺序）。还原后实测 17 处时刻与初始快照逐站一致。
- **诚实细节**：`clock` 区间与 `duration` 打架时以 duration 为准重串，但会在 console 醒目报警（本轮就抓到 Bamu
  写了 13:30–14:00 却配 duration 20，已修数据为 30）；详情卡「计划时间」旁的小字注随状态切换
  （没动过「按营业时间排定」/ 动过「已按停留与衔接顺延」）。

### 「数据与渲染解耦」的三次兑现

同一个原则：**app.js 不存任何城市名 / 天数 / 地点数 / 产品名**，只对结构负责；改完数据自然就成了新行程。
下面是从 v1.2 → v1.5 的三个真实例子。

**① v1.3 · 两天并成一天**：用户要求把原「第 1 天半岛 / 第 2 天路环」压成一天，数据侧 `DAYS` 从 2 条减到 1 条 + 14 处 `day` 全部置 `0`，
`app.js` 一行没动——路线 `DAYS.forEach` 自动只剩 `route-0`，编号 `renumber()` 自动从 `1-1`…`1-13` 重排为 `1-1`…`1-14`。
**但文案会露馅**：「逐天看」「点一天」「全部 1 天」这种说法只在两天以上才自然，于是所有天数相关文案都跟着 `DAYS.length` 走：

| 位置 | 多天时 | 单天时 |
|---|---|---|
| 顶部副标题 | `MACAU · 2 日行程` | `MACAU · 1 日行程` |
| 总览小标题 | 「这 2 天怎么走」 | 「这一天怎么走」 |
| 面板副标题 | 「点一天，看当天的路线」 | 「按时间顺序串成一条线」 |
| 天数标签行 | 总览 / 第 1 天 / 第 2 天 | **整行不显示** |
| 排序作用域提示 | 「全部 2 天」 | 「第 1 天」（而不是「全部 1 天」） |

天数标签行整行隐藏的理由很直接：「总览」与「第 1 天」在只有一天时内容完全一样，留着只是让人多点一次。

**合并的代价要如实写出来**：黑沙海灘现在 18:25 到，而 9 月下旬澳门日落约 18:20——**看到的是暮色里的海滩，
不是原笔记那种大白天**。这一条同时写进了 `data/places.js` 的 `hac-sa.desc` 与 [`Passage_3c 交付明细与对照矩阵.md`](./Passage_3c 交付明细与对照矩阵.md) 的 ⚠️ 提示，没有藏起来。

**② v1.4 · 拱北口岸作为跨城起点**：用户指定「我们从拱北口岸出发」，新增一处珠海侧口岸。
**性质完全不同**——跨城、非笔记来源、无配图、新分类（交通）。三处改动：

| 差异 | 处理 |
|---|---|
| 珠海侧 | 数据显式标 `cat: "交通"`，成第 5 个筛选大类。**不用改 app.js**——`ALL_TYPES` 本来就会把 `CAT_ORDER` 之外的分类追加到末尾 |
| 非笔记来源 | 详情卡底部的「内容来源」原本写死成「用户提供的小红书笔记」，加可选的 **`srcNote`** 字段：给了就用数据的，没给仍走默认 |
| 无配图 | 不需要改代码：`normalize()` 里 `p.thumb` 从 `imgs[0]` 推出，没有 `imgs` 就是空串，列表行直接不渲染缩略图 |

编号照旧由 `renumber()` 算出 `1-1`…`1-14`，其余 13 处自动后移一位。
**`app.js` 只动了 2 行**（`srcNote` 的读取与默认值列表）。

### 退化保护（v1.5 新增）

v1.5 加中山那天之后，**理论上会出现只有 1 个地点的日期**——比如用户删中山第 1 天的两个地方、就剩中山站。
那天会产生两个坑：

**坑 ① 1 点 LineString**：GeoJSON 规范要求 `LineString` 至少 2 个坐标。
实测（MapLibre GL JS 5.24）：塞 1 个坐标**不会抛错**，图层照样建起来，只是渲染时没有任何输出——即「不报错的静默失败」，比抛错还难排查。
所以 `addRoutes()` 里先 `if (routeCoords(d.index).length < 2) return;`，半天日期就不建路线图层。

**坑 ② 1 点 fitBounds**：包围盒退化成「一个点」、宽高都是 0。
实测：`fitBounds` 在 `maxZoom: 14` 下能正常把缩放顶到 14、中心落在该点——结果与下面这段显式 `easeTo` 完全一致。
但这个正确结果依赖 `maxZoom` 恰好设了 14、以及 MapLibre 肯把内部 `Infinity` 一路算下去，所以仍然写明：

```js
if (pts.length === 1) {
  map.easeTo({ center: [pts[0].lng, pts[0].lat], zoom: 14, pitch: CITY.pitch,
               bearing: CITY.bearing, duration: state.reduceMotion ? 0 : 900 });
  return;
}
```

**坑 ③ `autoSort` 对半天日期**：原代码会把 `< 3` 个点的日期跳过但仍报「当前顺序已经是最短的」，让用户以为算过。
改成给一个专门的提示 `可排序的地点少于 3 处，没有可优化的折返`，并在 `sortSnapshot = null` 不留撤销按钮。

### 调试句柄（v1.5 新增）

`window.PASSAGE` 是只读调试句柄，给无头 Chrome + CDP 验证脚本用：

```js
window.PASSAGE = {
  map: function () { return map; },     // 地图实例
  data: D,                              // 规整后的数据
  state: state,                         // 当前视图状态
  days: function () { return DAYS; },
  places: function () { return PLACES; },
  routeLayer: function (i) {            // 'no-map' | 'missing'（没建） | 'visible' | 'none'（隐藏）
    if (!map) return 'no-map';
    var id = 'route-' + i + '-line';
    if (!map.getLayer(id)) return 'missing';
    return map.getLayoutProperty(id, 'visibility') || 'visible';
  }
};
```

之前验证脚本只能从 DOM 反推（`.place-row` 数行、`/.*/.test(textContent)`、标记数量），
地图实例与 `DAYS/PLACES` 都在 IIFE 闭包里、拿不到——加了半天 / 退化保护之后要确认「`routeLayer(0)` 是否真的 `missing`」
就只能靠这个句柄。**全是取值函数 / 数据，不暴露任何写入口，也不参与业务逻辑**。

### 横向椭圆编号标记（v1.5 新增）

用户反馈两位数编号（如 `2-14`）在原来的 30×30 固定圆里被硬塞，只能靠 `.is-long` 缩字号。
改成胶囊形（其实是 `border-radius:50%` 配非正方形宽高 → 真椭圆）：

```css
.place-badge{
  height:28px; min-width:28px; padding:0 8px;
  border-radius:50%;   /* 椭圆的关键：非正方形宽高 */
  ...
}
```

实测尺寸：

| 编号 | 字符数 | 宽 × 高 (px) |
|---|---|---|
| `1-1`（最短） | 3 | 34.1 × 24 |
| `2-6` | 4 | 39.9 × 28 |
| `2-14`（最长） | 5 | 46.5 × 28 |

字号不再按编号长度分档，**所有徽章都 11px**。同步把 `SPREAD_MIN` 从 34 提到 44（贴 `2-14` 实际宽度取整）、
`SPREAD_MAXOFF` 从 24 提到 28，并把 `spreadMarkers()` 绑到 `moveend`——这样 `fitBounds` 后（`zoom` 不变的情况）也会重排，
`zoomend` 不触发、`moveend` 触发。

附带清理：`is-long` 这个 class 在 `place-badge` 上不再有 CSS 效果（只有列表里的 `.pr-badge` 仍在用，逻辑不变），
js 里也不再给它加 class。

### 移动端适配（v1.3 新增）

手机上用的是**底部抽屉**：行程面板默认收起成一条（只露标题栏），点标题栏展开；地点详情是更靠前的一层浮层。
横屏（矮屏 + 够宽）换成**左列表 + 右详情**——390px 高的视口里，底部抽屉会把地图压成一条缝。

这一轮修掉的问题，全部是先用脚本量出来的，不是靠肉眼估：

| 问题 | 原因 | 处理 |
|---|---|---|
| 地图底部溢出视口 24px | `#view-map{height:calc(100vh - 57px)}` 里的 57px 是桌面端顶栏高度；窄屏顶栏换行后是 81px | 拆掉写死的数字，改成 `body` 纵向 flex + `#main{flex:1}`，地图高度由剩余空间算出来；同时用 `100dvh` 让地址栏收放时也跟着变 |
| 收起态面板把页面顶出滚动条（文档高 1040 vs 视口 667） | 收起用 `transform:translateY(calc(100% - 152px))` 往下平移，整块被推出视口 | 改成收缩 `max-height`（面板自身 `overflow-y:auto`），不再平移 |
| 收起后露出的高度对不上 | 152px 是写死的，标题换行就错位 | `app.js` 实测标题栏高度写进 `--panel-peek`，CSS 用它 |
| 展开后地点列表只剩几十像素 | 面板内固定块（标题栏+天数+排序+摘要+筛选+底栏）加起来超过面板高度，列表被压成 0 | 面板整体滚动而不是只让列表滚；摘要里的地点串裁成一行；天数与筛选改单行横滑 |
| 天数标签被挤成一条线 | `.daytabs` 加了 `overflow-x:auto` 后成了滚动容器，而 flex 的「自动最小尺寸」对滚动容器是 **0** | 显式 `flex:0 0 auto` |
| 触控目标普遍偏小 | `.nav-btn` 30px、`.daytab` 31px、`.chip` 24px、`.btn-sm` 29px、MapLibre 控件 29px | 窄屏统一抬到 ≥44px（Apple HIG / Material 下限） |
| 地图标记点不中 | 圆点只有 30px | v1.4 圆点视觉放大到 34px；v1.5 改成横向椭圆（高度 28/32px，宽随编号长度 34–46px），同样用透明伪元素 `inset:-8px` 把**可点区域**撑到 ≥44px（直接画成 44px 会让十几个地点在澳门糊成一片） |
| 地图角标被收起态面板压住 | 图例、比例尺、署名都在 `bottom:10~16px` | 用 `--panel-peek` 把它们抬到面板上方 |
| 横屏列表完全看不到 | 左栏只有 320px 高，固定块就有 400px | 用 flex `order` 把摘要与底栏在视觉上挪到列表后面（DOM 不动），整栏滚动 |

还顺手加了：抓握条（提示可收起）、标题栏吸顶（滚下去也能收起）、安全区留白（`env(safe-area-inset-*)`）。

### 其他

- **减少动效开关**：关闭所有过渡动画，尊重 `prefers-reduced-motion`
- **响应式**：三个布局，同一个 980px 宽度阈值分叉——宽屏三栏 / 竖屏底部抽屉 / 横屏左列表右详情
- **无障碍**：地图信息有列表替代视图；标记带 `aria-label`；正文对比度达标
