# 文档维护约定 — Passage 文档体系规则（权威源）

> **职责**：文档体系规则本身的唯一权威源——目录结构、体积预算、维护规则、归档编号。
> **体积**：见自检（上限 8 KB）｜**更新**：2026-09-28（体系落地）
> **上级索引**：`Passage_0 文档地图.md` §2
> **本文不包含**：开发记录格式 → `AGENTS_记录规范.md`；为什么按场景分层（原理）→ 仓库根 `skills/docs-system-template/` SKILL.md
> ⚠️ **什么时候读本文**：**只在调整文档结构、新增文档、拆分文档时读**。日常写码不用读。

## §1 体积预算（与 `tools/doc-size.sh` 绑定，两处不一致本身就是缺陷）

| 层 | 文件 | 上限 | 依据 |
|---|---|---:|---|
| L0 地图层 | `Passage_0 文档地图.md`（docs/README.md 已并入，2026-09-28） | 8 KB | 地图自己不能成为负担 |
| L1 必读层 | `AGENTS.md` / `Agent交办事项.md` | 28 / 20 KB | 每次开工都读，最贵的字节 |
| 开工前置 | `AGENTS_记录规范.md`、`AGENTS_平台规范.md` | 8 KB | 动手前按需读，不能膨胀 |
| L2 按需层 | `Passage_1/2*/4*`、`engineering/*` | 24 KB | 一次读完 ≈ 5.5 K token |
| L2 状态类 | `Passage_3*` | 36 KB | 表格密集，但只服务「查进度」场景 |
| L3 归档层 | `archive/*` | 64 KB | 归档也要保证「只读其中一份」 |
| 流水 | `development-logs/` | **不设上限** | 随记录单调增长，拆分救不了；**不要通读** |

- 体积用 `wc -c`（1024 进制）实测，**别心算**（R7：头部体积失真与断链同级）。
- **余量阈值**：任何文档余量 < 上限 5% 时，下一次新增之前先拆，不等破线。
- 收尾跑 `bash docs/tools/doc-size.sh`，退出码必须 0；越线当场拆或归档，不留给下一轮、不抬上限（R6）。

## §2 维护七规则

1. **R1 先归属，后拆分**——多数「太长」是内容错位，先问「这段属于这份文档的职责吗」。
2. **R2 按阅读场景切**——每份文档必须能一句话回答「什么时候读我」，答不出就不该存在。
3. **R3 命名**——同主题子文档用字母后缀（`_2b`、`_3c`）；**字母后缀一律不进必读路径**；主文档放最高频部分。
4. **R4 头部元数据块**——每份必写：职责 / 体积 / 上限 / 更新 / 上级索引 / **本文不包含** / 什么时候读。
5. **R5 引用代替复制**——同一事实只写一处；引用必须**带节号**（`见 X.md §3`）。
6. **R6 越线即负责**——见 §1。
7. **R7 体积与断链同级**——头部体积失真、超预算未处理，都算维护缺陷。

## §3 新增文档的前置问题

每增设一份都要先回答「**哪个场景读它**」，答不出就不建。本项目已有编号口径：

- 主文档 `_1`（业务规则、优先级、路线与验收）→ `_2`（产品设计）→ `_2b/2c/2d/2f/2g`（子主题，字母后缀）→ `_3`（交付状态）→ `_3b/3e`（状态子文档）。
- **已退役编号不复用**（2026-09-28 合并退役）：`2e`→并入 `_1`、`3c`→并入 `_3b`、`4`→并入 `_2b`；docs/README→并入文档地图。
- **字母后缀不进必读路径**；新增子主题续编字母（`_2h`、`_3d`…），状态类新文档从 `_3b` 往下排，**不复用已占用编号**。

## §5 归档区规则

1. **原文一字不改**：搬入时整段搬运，只加 4 行归档页眉（本文件是历史归档 / 收录范围 / 什么时候读 / 当前状态请读 X）。
2. **不再更新**：历史在这里冻结，新历史由 `development-logs/` 承接。
3. **编号**：`A` + 两位序号 + 空格 + 名称（`A01 文档沿革-v1.1至v1.5.md`）。**新增一律追加到末尾，不复用、不插入、不重排**。
4. **引用一律带编号**：写法 `docs/archive/A01 文档沿革-v1.1至v1.5.md`。
5. 归档内容若已被提炼进现行文档，在 `archive/README.md` 写明「沿革出处 → 现行权威源」映射。

## §6 自产技能包（skills/）

仓库根 `skills/` 不受 docs 预算约束、不按文档层管理；**skill 正文不抄进 docs**，docs 里只写指针（见 `Passage_0 文档地图.md` §4）。
