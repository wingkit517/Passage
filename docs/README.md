## 一句话结论

**开源社区有可复用的「功能基座」（TREK，8/8 能力覆盖），但没有可复用的「产品形态」。**

所以要做的不是「换皮」，而是**拿 TREK 当后端，自建体验层**——因为小红书那篇的真正价值（原创城市插画、鸟瞰地图、电影式镜头推进）在开源社区没有对应物。

> **v1.1 变更**：砍掉「电子手帐 / 旅行箱物件墙」，产品收敛为**纯行程工具**。
> 产品定位从「出发前是攻略，回来后是纪念品」收窄为「**把散落各处的攻略，收敛成一条走得通的路线**」。
>
> **v1.2 变更**：数据从 3 处扩到 **13 处 / 2 天**（用户陆续补了 7 条笔记）；
> 每处补上**来自笔记的实拍配图**（可点开看大图）；详情卡补上**关闭按钮**（× / Esc / 点地图空白）；
> 左侧列表加缩略图；新增 [`04-澳门行程清单.md`](./04-行程清单-中山与澳门.md) 作为行程的单一事实来源。
>
> **v1.3 变更**：**两天并成一天**——原「第 1 天半岛 / 第 2 天路环」改为「上午半岛 → 下午路环 → 傍晚氹仔收尾」。
> 路环 7 处地点名称统一加 **【路环】** 前缀；编号重排为 `1-1`…`1-13`。
> 前端同步做了单日适配（`app.js` 里天数相关的文案跟着天数走，只有一天时隐藏天数标签行）。
> 另新增移动端底部抽屉布局（见 [`05-原型实现说明.md`](./05-原型实现说明.md)）。
>
> **v1.4 变更**：新增起点 **拱北口岸**（珠海侧，用户指定），列为第 1 站；其余 13 处编号后移为 `1-2`…`1-14`；
> 新增 **「交通」分类**（与餐饮 / 景点 / 街区 / 海滩并列）；全天跨度提前为 **06:45 – 20:25**。
> 另：**地图库改为随仓库内置**（`vendor/maplibre/`，不再依赖 CDN），并给详情卡的「内容来源」加了按地点覆盖的能力
> （拱北口岸不是笔记来源，不能沿用「内容来源：用户提供的小红书笔记」这句默认文案）。
>
> **v1.5 变更**：**行程从 1 天拆成 2 天**——原澳门全天改为「第 2 天 · 澳门」，
> 新建「第 1 天 · 中山」（傍晚）作为前置行程，3 处地点全部按用户给出的链接入库：
> **中山站**（用户指定，OSM 节点 18:00 出发）、**松本工坊·寿司（礼和店）**（日料晚餐，10:30–20:00）、
> **圆宝阿公**（台式甜品，13:00 起叫号入座）。产品名定作 **Passage**，从数据层 `APP.name` 取，不再散落硬编码。
> 地图徽章从固定 30px 圆改为**横向椭圆**（宽度随编号长度走），两位数标签不再被圆裁掉；同步给松弛避让提高 `SPREAD_MIN/MAXOFF`
> 并把 `spreadMarkers` 绑到 `moveend` 让平移 / fitAll 后也重排。
> `app.js` 加了**对退化输入的防御**：只有 1 个地点的日期不再塞非法 1 点 LineString、单点 `fitBounds` 走显式 `easeTo`；
> `autoSort` 给出更诚实的「少于 3 处，没有可优化的折返」文案。
> `data/places.js` 顶部数据来源注释、04 行程清单、05 实现说明、README、截图目录全部按 v1.5 重写。

## 已经跑起来的原型

**站点文件在仓库根目录**（`index.html` / `styles.css` / `app.js` / `data/` / `assets/`），
是一个**零构建的静态原型**，覆盖了 `02-产品设计方案.md` 里 Phase 1（MVP）与 Phase 2 的「路线自动排序」：

```bash
# 在仓库根目录执行
python3 -m http.server 8777 --bind 127.0.0.1
# 打开 http://127.0.0.1:8777/
```

两个视图：行程总览（规模统计 + 每天路线卡）、地图工作台（三栏联动）。

**当前数据：中山 · 澳门（17 处地点 / 2 天 / 24 张配图）**，来源是用户提供的 9 条小红书笔记链接 + **2 处用户指定的起点**（中山站、拱北口岸）。
第 1 天中山（傍晚）18:00 中山站出发 → 松本寿司晚餐 → 圆宝阿公糖水冰；第 2 天澳门（全天）06:45 拱北口岸过关 → 半岛上午 → 路环下午 → 氹仔糖水收尾。

原型截图见 [`assets/原型截图/`](./assets/原型截图/)（**15 张**：行程总览、地图工作台、**第 1 天中山**、**第 2 天澳门**、5 张详情卡（中山站 / 松本寿司 / 圆宝阿公 / 拱北口岸 / 好利是）、大图查看、关闭后空态、3 张移动端、1 张横屏）。

**已经验证可用的核心能力**：

- 倾斜鸟瞰地图（pitch 50°）+ 真实 3D 建筑挤出
- 17 个地点的编号标记，按天着色（`1-1`…`1-3`、`2-1`…`2-14`），**横向椭圆**（v1.5）—— 宽度随编号长度走
- 两条彩色虚线路线 + 相位平移的「流动」动画（按天着色）；半天日期自动不建路线（防止非法 1 点 LineString）
- 点击地点镜头飞近（zoom 16.2 / pitch 55°）+ 详情卡展开
- **路线自动排序**：最近邻 + 2-opt，带前后距离对比、一键撤销、起点锁定
  （v1.5 实测跨两天 17 处：28.7 km → 23.1 km，**省 5.5 km（−19.3%）**；半天日期如实报「少于 3 处，没有可优化的折返」。
  口径是地点之间 **haversine 直线距离之和**，只用于比较两种顺序的相对长短，不是步行里程）
- 地点详情含**地址 / 营业时间 / 电话 / 价位 / 怎么去 / 坐标精度**，逐条标注来源
- **每处地点带 1–2 张来自笔记的实拍配图**，图下带说明，点图可看大图
- **详情卡可关闭**：右上角 ×、Esc、点地图空白处；未选中时按钮自动隐藏
- 左侧列表带 42px 缩略图（专用 `thumb.jpg`，15 张共约 110 KB，不是直接塞原图）
- 移动端底部抽屉布局、减少动效开关
- **数据与渲染完全解耦**：`app.js` 里没有城市名 / 天数 / 地点数 / **产品名** 的硬编码

**还没做**：真实后端、攻略导入产品化、协作、预算、离线。这些需要接入后端（建议复用 TREK）。

> ⚠️ 必须走 http 服务打开，不能双击 `file://` —— 地图瓦片是跨域请求，`file://` 下会被浏览器拦截。

## 三分钟读完的要点

### 1. 开源调研结论（详见 01）

| 层面 | 结论 |
|---|---|
| 功能基座 | ✅ 存在。`liketrek/TREK`（AGPL-3.0，≈14.4k Star，2026-09-26 仍更新）对 8 项核心能力全覆盖，一条 `docker run` 起服务，自带简繁中文 |
| 产品形态 | ❌ 不存在。没有任何开源项目做「视觉叙事型个人旅行工作台」 |

**核心判断**：TREK 是**工具型**（把旅行管起来），小红书那篇是**叙事型**（把旅行记住并讲出来）。信息架构从根上不同，**换皮做不出来**。

### 2. 产品定位（详见 02）

**一个把散落各处的旅行攻略，收敛成一条走得通的路线的工作台。**

- 两条原则：**顺路优先于好看** · **一个主场，做透**
- 一个主场：地图工作台（加一个总览入口）。不做行后记录
- v1 明确不做：多人算账、实时比价、社交 feed、全球城市（只做澳门）

### 3. 技术路径（详见 03）

```
自建体验层（原型：原生 JS 静态页 / 目标：React 19 + MapLibre GL JS）   ← 主要工作量
      ↓
复用 TREK 能力层（行程/协作/预算/附件/导出/离线）
      ↓
自建内容层（攻略采集：笔记链接 → 结构化地点 + 资料来源管理）          ← 产品护城河
```
