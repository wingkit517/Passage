### 8.1 首页 · 行程总览

**设计意图**：第一眼回答「这份行程是什么」——几天、去哪、每天怎么串。不做仪式感动画，做**信息密度合适的概览**。

- 顶部信息块：行程标题 + 一句说明 + **规模统计**（天数 / 地点数 / 周边餐饮数 / 建议停留合计）
- 每日路线卡（3 列，窄屏 1 列）：`第 N 天` + `主题` + `地点 A → B → C` + `建议停留合计约 X 小时`
- 每张日卡是**进入地图的入口**，点击后跳到地图工作台并自动切到当天
- 入场动效：信息块与卡片依次淡入上浮（约 550ms，逐级延迟 50–70ms），**可重播**

### 8.2 地图工作台

**布局**（桌面）

```
┌──────────────────────────────────────────────────────┐
│ [中国澳门 · 3 PLACES]                                 │
├────────────┬──────────────────────────┬──────────────┤
│            │                          │              │
│  行程面板   │       鸟瞰地图画布        │  地点详情卡   │
│  (320px)   │                          │   (360px)    │
│            │                          │              │
│ · 日期 Tab  │  · 倾斜 45–60° 视角       │  按需展开     │
│ · 路线摘要  │  · 3D 建筑               │              │
│ · 类型筛选  │  · 编号标记 1-1, 1-2…     │              │
│ · 地点列表  │  · 每日彩色虚线            │              │
│            │                          │              │
└────────────┴──────────────────────────┴──────────────┘
```

**布局**（移动端 < 768px）

- 地图全屏
- 行程面板从底部抽屉拉出（半屏 / 全屏两档）
- 详情卡从底部弹出，覆盖地图下半部
- 编号标记缩小，虚线加粗保证可见

**地图关键参数**

| 参数 | 取值 | 说明 |
|---|---|---|
| 初始 pitch | 50° | 倾斜鸟瞰，能看到建筑立体感 |
| 初始 zoom | 13 | 能看清街区与主要地标 |
| max pitch | 60° | 再高会看不清地名 |
| 建筑挤出 | 开启（3D buildings） | MapLibre + OpenFreeMap 即可实现（fill-extrusion 依赖瓦片里的建筑高度字段）；Mapbox 的立体质量与地形更好，但需 token 且收费 |
| 标记样式 | 圆形徽章，白底 + 当天主题色描边 | 内显编号如 `1-3` |
| 路线样式 | 虚线，宽度 3px，圆头 | 每天一色 |
| 镜头飞近 | `flyTo` + 缓动，时长 1200ms | 同时抬高 pitch 至 55°，强化「飞近」感 |

### 8.3 地点详情卡

固定结构（字段顺序不可变，保证浏览一致性）：

```
┌─────────────────────────────┐
│ [彩色头部块]                  │
│  英文小标：SHANGHAI FIELD GUIDE │
│  类型 · 气质：地标 · 石库门夜色   │
│  地点名：新天地（大字）          │
│  [时段 pill] [停留时长 pill]     │
├─────────────────────────────┤
│ 正文描述（2–3 句）              │
│ [配图]                        │
├─────────────────────────────┤
│ ☕ 先去吃什么                   │
│    店名 + 地址 + 一句提示        │
│ 🏞 去哪里看风景                 │
│    点位 + 一句提示              │
│ 查看资料来源 ↗                  │
└─────────────────────────────┘
```

**设计要点**：
- **头部块颜色随地点变化**（原文中愚园路是橙红、静安寺是姜黄、新天地是品红）——形成视觉记忆点
- 时段与停留时长用 pill 呈现，一眼可读
- 「查看资料来源 ↗」必须有，这是内容可信度的保障

### 8.4 路线自动排序（v1.1 新增 P0）

- 入口：行程面板底部的「自动排序」按钮，按天生效
- 算法：**最近邻构建初始路径 → 2-opt 消除交叉**，距离用 haversine
- 约束：支持**锁定锚点**（如酒店、预约制景点），锁定点不参与重排但在计算距离时作为必经点
- 输出：排序后即时更新路线虚线、地点列表顺序、标记编号
- 安全阀：排序前快照当前顺序，提供「撤销排序」回到手工顺序
- **必须显示排序收益**：如「总步行距离 8.4 km → 6.1 km，减少 27%」。没有可感知的收益，用户不会信任自动排序

### 8.5 交互边界（v1.1 明确不做）

以下能力**不在 v1 范围内**，写在这里是为了防止实现时「顺手加上」：

- 行后内容：手帐、照片墙、票根、纪念品、心情标签
- 多人协作编辑与评论
- 行程模板市场 / 社区分享
- 实时交通与拥堵规避

## 三、附：参照笔记的原始制作路径（供参考）

原作者的实现方式是「用 AI 工具直接生成网站」，路径为：

1. 在千问中选择「工作」模式，调用「网页应用创建」Skill
2. 输入一段完整的产品需求指令（含视觉风格、地图交互、行程组织方式等）
3. 把收藏的攻略丢进知识库，让 AI 参考后继续规划

**对本项目的启示**：这套流程证明了「单人 + AI 能在几天内做出这样的产品」，但它的产出是**一次性、单城市、不可维护**的静态站点。本项目要做的是把同样的体验**产品化**——有数据模型、可换城市、可长期维护。

> 说明：以上路径仅为对参照笔记内容的客观转述，用于理解原作者的实现方式，不构成本项目的技术选型建议。
