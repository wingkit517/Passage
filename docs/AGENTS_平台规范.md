## 一、运行

```bash
# 在仓库根目录执行
python3 -m http.server 8777 --bind 127.0.0.1
# 打开 http://127.0.0.1:8777/
```

> ⚠️ **不要用 `file://` 直接打开**。地图瓦片是跨域请求，`file://` 协议下浏览器会拦截，底图加载不出来。必须走 http 服务。

## 三、文件结构

站点文件全部在**仓库根目录**（不再是 `app/` 子目录）：

```
<仓库根>/
├── index.html          # 两个视图的骨架
├── styles.css          # 全部样式（纸张底 + 每日主题色）
├── app.js              # 核心逻辑：数据规整 / 视图切换 / 地图 / 面板 / 详情 / 排序
├── data/
│   └── places.js       # 数据层：CITY + TRIP + DAYS + PLACES
├── assets/
│   └── places/<id>/    # 每处地点：1.jpg 2.jpg（长边 900px）+ thumb.jpg（180px）
└── vendor/
    └── maplibre/       # 内置的 MapLibre GL JS 5.24.0（js + css + LICENSE.txt，BSD-3-Clause）
```

这样 clone 下来起一个静态服务就是完整应用，也能直接挂 GitHub Pages。

> **为什么把地图库放进仓库**（v1.4）：原本从 `cdn.jsdelivr.net` 引入，2026-09-27 那次
> jsdelivr 在本机不可达（`curl` 返回 000，而瓦片源 `tiles.openfreemap.org` 正常 200），
> 结果**整块地图变成「地图库未能加载」**。一个号称「clone 下来就是完整应用」的零构建站点，
> 不该把核心渲染库挂在单一 CDN 上。落到本地后，1.03 MB 的代价换掉了这个单点故障。

### 数据与渲染是解耦的

`app.js` 里**没有任何城市名、天数、地点数量的硬编码**。换城市只需改 `data/places.js`。

数据规整全部集中在 `normalize()` 一个函数里（`app.js` 第 49–138 行附近），它负责：

1. 补 `CITY` 默认值，`en` 缺失时从 `name` 派生
2. `DAYS` 缺失时按地点里出现的最大 `day` 推算，颜色从 `DAY_PALETTE`（10 色）循环取
3. 补地点字段默认值；缺经纬度的地点置 0,0 并 `console.warn`
4. 按 `order` 排序并重编 `badge`（`1-1`、`1-2`…）
5. `CITY.center` 缺失时用地点的包围盒中心
6. `TRIP` 统计（地点数 / 天数 / 餐饮数 / 建议停留）现算，避免与真实数据不一致

**验证方式**：用一个只有「地点名 + 经纬度 + 第几天」的 12 地点京都数据替换 `places.js`，
页面仍完整渲染——标题变「京都旅行工作台」、徽章变两位数、缺失字段优雅留空。

`data/places.js` 是**手工整理的**（见文件头注释），正式版应改为后端接口。
