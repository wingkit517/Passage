## §0 开工前检查清单

按序做完再动手，别跳：

1. 读 `Passage_0 文档地图.md`（路由表）→ 读本文 → 读 `Agent交办事项.md`（当前状态与下一步）。
2. 确认要改的是哪一层：数据（`data/places.js`）／渲染（`app.js` `styles.css` `index.html`）／文档（`docs/`）。
3. 数据层改动后，**同步** `Passage_3c 交付明细与对照矩阵.md`——两者是同一事实的两处呈现，改一边必须改另一边。
4. 收尾前跑 `bash docs/tools/doc-size.sh`，EXIT 必须为 0。
5. 用户明确要求过：**每次修改完都推送到远端**（`git push origin main`）。

## §1 纪律：如实标注未验证

**这一条是整份文档的灵魂。** 做不到就别写：

- 测试**没跑**就写「未跑」；验证**不到**就写「未验证」；**禁止**把「编译通过 / 页面能打开」记成「测试通过」。
- 数值必须标来源与精度：坐标标精度分级（楼宇级 / 车站级 / 街道级 + 误差米数），营业时间标「官方渠道 / 第三方转引 / 笔记实证 / 未核实」。
- **不许拔高精度**：街道级就是街道级，不能因为「大概是那栋楼」就写成楼宇级。
- 断言脚本里写错的**期望值**不许改断言去迁就实现——先判断是断言错还是实现错。本次重构中就出现过 3 条我自己写错的断言（把「第 1 天有 3 处」误设成 1 处），是改断言而非改代码。
- 未解决的事写进 `Passage_3b 决策·风险与缺口.md` §三，不许在正文里悄悄省掉。

## §5 领域硬约束

**5.1 数据层是唯一权威源。** 全部地点事实只在 `data/places.js` 写一次。`Passage_3c 交付明细与对照矩阵.md` 是它的**文档化呈现**，两者同源、改一处必改另一处。任何第三处出现地点事实 = 副本，副本会互相矛盾。

**5.2 渲染层零硬编码。** `app.js` 里**不得出现**城市名、天数、地点数、品牌名的字面量。默认值一律由 `normalize()` 兜底。这条已被兑现三次（v1.3 换城市 / v1.4 加起点 / v1.5 换品牌名 + 拆两天），每次都是只改数据不动代码——**别把已经还掉的技术债再借回来**。

**5.3 品牌名只此一处。** `window.TW.APP.name`。改产品名改这一处即可，不许散落在 HTML / JS / 文档标题里。

**5.4 徽章编号自动派生。** `p.badge = (d.index + 1) + '-' + (i + 1)`。新增 / 删除 / 移动地点时**不需要**手工改编号，也不许手工改。

**5.5 零构建。** 纯静态站点，原生 JS，无打包器、无框架、无 `npm install`。地图库已 vendor 到 `vendor/maplibre/`（离线可用）。**不许引入构建步骤**，这是本项目的形态选择。

**5.6 缩略图从 `imgs[0]` 派生。** `p.thumb` 不手工填；`imgs` 为空则该行不显示缩略图、详情卡无画廊——这是设计好的行为，不是 bug。

**5.7 地图标记散开与退化保护。** `spreadMarkers` 同时绑 `zoomend` 与 `moveend`（纯平移不触发 `zoomend`）；路线坐标少于 2 个时不建图层；单点 `fitAll` 走 `easeTo` 分支。改这三处前先看 `engineering/踩坑与原理.md` §1。

**5.8 移动端基线。** 390×844 下必须无横向溢出、无底部溢出、无 <44px 触控目标。改动 CSS 后要复测。

## §6 构建与执行纪律

- 本地起服务：`python3 -m http.server 8777`（仓库根），打开 `http://127.0.0.1:8777/`。详见 `AGENTS_平台规范.md` §1。
- 改数据后跑一遍数据自检（node 载入 `data/places.js`，核对地点数 / 徽章序列 / 停留总时长 / 图片数）再提交。
- 无证断言（headless Chrome + CDP）需要四个参数齐备：`--no-sandbox --use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`；CDP 调用要带超时；**轮询 readiness，不要固定 sleep**。
- 截图脚本点击一律用 `.place-row[data-id="…"]`，**不许用 `.place-row[n]` 下标**——新增地点会让每个下标整体漂移。

---

## §7 自动化断言与取证

- 断言脚本按 `data-id` 定位，找不到行直接 throw，不许静默点空。
- 取证要留证据：截图、DOM 实测值、字节数。**不要凭印象写「已验证」**。
- 越线 / 失败的断言要写清楚是「断言写错」还是「实现有问题」，不许含糊过去。
- 收尾跑 `bash docs/tools/doc-size.sh`，越线当场拆或归档，不留给下一轮。

---

## §8 禁止事项清单

1. ❌ 把「编译通过 / 能打开」写成「测试通过」。
2. ❌ 拔高坐标精度、省略来源、把未核实写成已核实。
3. ❌ 在 `docs/` 里复制 `data/places.js` 的地点事实（要写就写指针 + 节号）。
4. ❌ 新增文档却不回答「哪个场景读它」——答不出就不建。
5. ❌ 在 `app.js` 里写死城市 / 天数 / 地点数 / 品牌名。
6. ❌ 手工改徽章编号（`N-M` 是派生的）。
7. ❌ 引入打包器 / 框架 / 依赖安装步骤。
8. ❌ 回改已完成的开发记录（要补充就写新记录）。
9. ❌ 未经用户确认就做对外动作（推送以外的公网写操作、发消息、发布）。
10. ❌ 归档区重排 / 插入 / 复用编号（一律追加到末尾），否则已发出的外部引用会指向错误内容。
